# 005 — Evolution 记录

> 记录从选题卡片到各版草稿的写作决策、演进节点和待办手术点。

---

## Draft 1.0 — 结构定型版（2026-06-06）

### 一、这版从"builder 视角"转成了"user 视角"

上一轮卡片里，文章的隐含主语仍然有一点偏 builder：平台会不会吃掉工具型 Agent？OpenClaw / Hermes / Reasonix 应该怎么定位？这会自然把读者收窄到开发者、创业者、产品经理。

这版 draft 1.0 里，主语换成了普通但高频的 AI 使用者。正文里反复使用的不是"开发者如何构建 Agent"，而是"内容创作者、销售、创业者、小团队 owner 为什么会发现平台 Agent 还不够懂自己"。

这个变化的好处是扩大受众。读者不需要正在做 Agent 产品，也能进入问题。他只需要有一个体验：AI 工具很多，但每一个都像第一次认识我。

这是更大的情绪入口。

### 二、Coze 3.0 被降级为入口，不再承担全文主角

原始素材是 Coze 3.0 产品观念映射分析，但这版没有写成 Coze 3.0 发布会复盘。原因是如果一上来讲 Coze 的功能、skill、workflow、平台经济学，文章会马上进入产品经理和 builder 的圈层。

所以 Coze 3.0 的作用调整为"信号"：它说明平台 Agent 正在变成公共工具箱。正文真正讨论的是平台 Agent 和个人 Agent 在用户工作中的分层。

这符合 002 的演进经验：去掉圈层脚手架，把专业判断翻译成普通读者能感受到的问题。

### 三、术语被刻意压低，尽量用生活化解释替代

这版有意少写 MCP、workflow node、RAG、function calling、skill store 这些词。不是因为它们不重要，而是因为这篇的读者不应该被限定在 builder。

对应替换如下：

| 原本容易出现的词 | draft 1.0 里的替代写法 |
|---|---|
| workflow | 工作流 / 真实工作方式 / 长期工作方式 |
| skill store | 公共工具箱 / AI 能力市场 |
| memory | 长期上下文 / 工作历史 |
| personal agent | 私人工作台 / 能记住自己工作历史的 AI |
| API 编排 | 把不同工具里的上下文连起来 |
| platformization | 通用能力平台化 |

这个处理延续了 002 README 里的原则：当一个专业词的解释比这个词更短、更生动时，就用解释替代专业词。

### 四、LF-3 概念锚定：用场景解释"长期上下文"

这篇最核心的抽象概念是"长期上下文"。如果直接解释，会变成 AI 产品分析文章；所以 draft 里用了三个场景来锚定：

- 内容创作者不是只要 AI 写文章，而是要 AI 知道账号历史、选题节奏、读者画像和表达偏好。
- 销售不是只要 AI 写邮件，而是要 AI 知道客户关系推进到了哪一步。
- 创业者不是只要 AI 总结会议，而是要 AI 知道公司为什么放弃某个方向、当前优先级是什么。

这三个场景的作用，是让读者先"撞见"长期上下文，再接受概念。

### 五、LF-4 叙事节拍：目前还有一点"论证文"味，需要 v1.1 再做人味手术

这版结构清楚，但还是偏"判断文"。它的好处是观点完整，坏处是人物感和现场感还不够。

尤其是第三节虽然用了创作者、销售、创业者三个场景，但它们还都是类型化人物，不是真正"活人"。这和 004 的经验有关：v1 可以先铺满结构，v2 再把讲述改成目击。

下一版可以考虑增加一个更具体的开头场景，比如：

> 一个内容创作者深夜打开 AI 工具，让它帮自己改一篇稿。AI 给出一版很完整的结构，但他越看越觉得不对，因为那篇稿子里有太多"正确但不属于自己"的句子。

这个场景可以替代现在相对抽象的开头，让读者更快进入。

### 六、LF-5 藏与露：已有金句，但还不够"藏在细节里"

这版有几句传播句：

> 平台 Agent 解决的是："我现在有一件事，帮我做掉。"
> 个人 Agent 解决的是："我长期就是这样工作，你要越来越懂我。"

> 平台 Agent 的优势是：它会很多事。
> 个人 Agent 的优势是：它知道我的事。

> 公共工具箱负责能力调用。私人工作台负责工作连续性。

这些句子适合作为公众号金句，但它们仍然是显性判断。按照 LF-5，下一版最好把其中一部分判断藏进细节里。例如不直接说"AI 不懂我"，而是写用户一次次重新上传材料、重新解释背景、重新纠正语气，最后产生"我怎么又在给它做入职培训"的疲惫感。

这一句"入职培训"目前已经放进正文，是一个可以继续展开的细节锚点。

### 七、LF-6 场景调性：避开了发布会喧嚣，但还需要更稳的开场画面

这版没有渲染 Coze 发布会，也没有写"大厂震撼发布"之类的喧嚣场景。整体调性是产业观察。

但它仍然缺一个更稳、更人文的开场画面。现在开头是问题式开场，适合判断文；如果要更像公众号长文，可以在 v1.1 改成一个具体用户工作场景，再自然引出问题。

可能的开场方向：

> 一个写作者第一次意识到 AI 不懂自己，不是在它答错问题的时候，而是在它写得太对的时候。

这句话有一点张力。因为"写得太对"反而"不像自己"，可以自然引出平台 Agent 与个人 Agent 的差异。

### 八、下一版 v1.1 的主要手术点

v1.1 不建议推翻结构，而应该做三件事：

1. **把开头改得更有场景。** 现在是概念问题开场，清楚但不够有画面。可以从"一个高频 AI 用户发现 AI 仍然不懂自己"的瞬间写起。

2. **把第三节的三类用户写得更具体。** 内容创作者、销售、创业者目前还是抽象类型，可以各自增加一两个动作细节，比如翻旧稿、查客户记录、会议后改待办。

3. **收尾再克制一点。** 现在最后一句"你还记得我在做什么吗？"方向对，但前面几段还有一点解释过满。可以在 v1.1 把结尾压短，让它更像 004 preview 那种独立短句收束。

**这版 draft 1.0 的定位是：结构定型版。** 它已经把受众、主线、核心判断和分层框架跑通。下一版应该做的是：把判断文改得更像有人正在真实使用 AI 的长文。
