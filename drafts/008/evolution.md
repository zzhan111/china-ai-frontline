## 2026-06-11 — v1.0 初稿生成 → v1.1 自评迭代

### 做了什么

基于选题卡片 `topics/pillar-X/008-dario-policy-exponential.md` 和两份调研材料（`REPORT.md`、`dario-essay-text.md`），生成 v1.0 初稿。结构为七段递进式：Treebeard 切入 → 政策拆解 → "为什么是现在"（三件套脉络）→ 社区反弹三类归纳 → "Dario 可能对但这仍然危险" → 中文圈为何容易错过 → 方向盘收束。

v1.1 自评后进行了五处结构调整：

1. 开头：Treebeard 从一整段压缩为两句话钩子，直接跳到"这篇文章争的不是要不要监管，而是谁来定义监管"。
2. 社区反弹段（原第三节）与产业定性段（原第四节）之间的"监管捕获"重复被消除。v1.1 中第三节只做社区情绪归纳（不评价），第四节独立做产业判断（制度竞争）。
3. 中文圈段落（原第六节）从独立章节压缩为结尾前的一段嵌入判断，不再单独成节，避免"附注感"。
4. 结尾从"方向盘"意象收束改为更锐利的产业判断："模型公司之间的竞争将从 benchmark 转向 regulatory framework。谁能把自己的安全框架变成行业标准，谁就能定义下一阶段的比赛规则"。
5. 全文增加了具体数据锚点（HN 138 pts / 198 comments 的时间窗口、"四类风险"的逐条标注、Dario 三篇政策文的发布时间顺序），增强调研感。

### 学到什么

- **热点调研型文章和访谈叙事型文章的结构逻辑不同**。访谈型（如 004）靠"人的故事 → 初心 → 实践 → 下一个想法"形成闭环，读者跟着人的轨迹走。调研型（如 006、008）靠"现象 → 拆解 → 多方观点 → 独立判断"形成闭环，读者跟着论证走。调研型对重复容忍度更低——同一个论点出现两次，读者会觉得你在凑字数而不是在推进。
- **​"承认对方合理性"这个策略在调研型里比叙事型更需要克制**。v1.0 在开头和第二节反复强调"Dario 的判断有事实基础""风险确实是真问题"，用意是避免写成阴谋论，但实际效果是论证节奏变慢。v1.1 把"承认合理性"集中压缩到第二节前半段，一次说完，不再反复。
- **社区反弹归纳需要和作者判断明确分层**。v1.0 的问题是，归纳完 HN 评论后立刻进入"Dario 可能是对的但这仍然危险"，读者分不清哪段是社区观点、哪段是作者观点。v1.1 用第三节纯做社区归纳（"他们反弹的是什么"），第四节纯做作者判断（"这意味着什么"）。

## 2026-06-11 — v1.1 → v1.2：信源显名化 + 调研透明性增强

### 做了什么

v1.1 的论证结构基本成立，但全篇几乎没有标注具体信源。读者看到"HN 上一条高赞评论说""Dario 在文中提到"，无法判断哪些是一手调研、哪些是作者归纳。v1.2 在不变动结构的前提下，做了四件事：

1. **HN 数据加时间戳**：每次引用社区讨论都标注数据窗口（"截至 2026-06-11 调研时刻，138 points / 198 comments / 46 top-level"），并在首次出现时注明数据来源（`REPORT.md` 通过 HN API 抓取）。
2. **关键引语加来源**：三条被引用的 HN 评论（监管捕获、强制闭源、PR 节奏论）全部补上 commenter ID 和原文措辞片段，读者可以自行溯源。
3. **Dario 原文引用加定位**：四个政策主张分别补了原文出处（所属章节 + 关键原句或段落位置），"四类风险"逐条标注来自原文 Section 1，"三件套"脉络补了三篇文章的标题和时间顺序。
4. **Anthropic 语境补了具体参照物**：Mythos Preview、scaling laws 10+ 年实证、Claude Economic Index、"a country of geniuses in a datacenter" 等关键词全部补了出处锚点，避免读者觉得是作者在替 Dario 脑补。

### 学到什么

- **调研型文章的信源透明性本身就是一种论证**。读者不需要每句话都看到出处，但关键判断点必须有"你可以自己查"的路径。否则"调研"两个字在读者那里立不住。
- **HN 评论引用要同时给时间和 ID**。只说"HN 上有人说"读者会怀疑你在选择性引用；给 ID 和时间窗口，相当于公开了你的采样方法，即使你选的是有偏向的子集，至少方法是可复现的。
- **Dario 原文引用最关键的不是逐字复述，而是让读者能定位**。"原文 Section 1 第三个政策建议"比"Dario 说……"更接近调研感，因为它在说：我读过了，你也能找到。

### 还没 close 的 open item

### 学到什么

- **C 类热点调研型的 preview 压缩策略和 B 类意见型不同**。B 类可以砍例子保留判断链，C 类砍的是"你不需要立刻知道但你调研过的东西"——比如三件套脉络的逐篇展开、中文圈独立章节。读者在窗口期内最关心的是"这事意味着什么"，不是"你调研了哪些材料"。材料完备性留在 README 和 evolution 里。
- **信源从脚注移到文末参考资料**不只是格式变化，它改变了阅读节奏。脚注打断论证流，但给读者"随时可以查"的安全感；文末参考资料不打断流，但要求正文里的关键事实更自洽。preview 选择了后者，因为公众号阅读场景下打断成本更高。
- **LF-8 传播锚点需要出现在结尾而非中间**。v1.2 把 Hobbits 意象放在最后一句，力度够但读者带走的不是一句话而是一个画面。preview 在结尾段同时保留画面和一句话锚点（"监管不是刹车，是方向盘"），兼顾文学性和传播性。
