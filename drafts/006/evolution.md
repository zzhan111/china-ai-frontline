## 二、选题迁移说明

原 006 的主题是 Agent 工具链，核心判断是“第二阶段不是模型竞赛，而是工具链竞赛；造车是进入第三阶段入口争夺的入场券”。

但 Fable 5 / Mythos 5 在 2026-06-09 发布后，出现了更强的热点窗口：

1. 事件密度足够高：官方发布、benchmark、英文社区、中文社区、价格变化、安全分层同时出现。
2. 争议点足够集中：强模型、贵模型、静默降级、订阅终结、能力分层。
3. 与长期主线相关：它并不只是模型新闻，而是直接指向 Agent 工具链、模型路由、成本控制和闭源模型透明度问题。
4. 时效窗口很短：发布 24-48 小时内最适合输出一篇全面调研型文章。

因此，本期 006 改为 Fable 5 热点调研；原 Agent 工具链文章顺延为 007，并可在 007 中承接本文最后提出的“强模型更需要工具链”判断。

## 三、v1.0 的结构设计

v1.0 采用“热点调研型文章”的递进结构，而不是意见型文章的“框架提出 → 案例验证 → 个人位置”结构。

### 1. 开头：从 subagent 误判切入

文章没有直接从“Fable 5 发布了”开始，而是从一个调研过程中的反常现象切入：

3 路 subagent 第一轮都判断 Fable 5 / Mythos 5 可能不存在。

这个开头有三个作用：

1. 给文章一个独特的第一手视角，而不是复述发布新闻。
2. 引出“热点事件必须真实联网验证”的调研方法。
3. 建立本文的可信度：不是跟风写，而是做了验证。

### 2. 第一层：承认它真的强

文章先完整承认 Fable 5 的能力跃迁，避免一上来为了反转而反转。

重点使用：

- SWE-Bench Pro：80.3% vs Opus 4.8 69.2%
- SWE-Bench Verified：95.0% vs Opus 4.8 88.6%
- FrontierCode Diamond：29.3% vs Opus 4.8 13.4%
- Simon Willison 的 “it's a beast”
- HN 与 V2EX 中关于复杂重构、逆向工程、前端还原的实测反馈

这一节的核心作用是建立“封神有事实基础”。

### 3. 第二层：指出“封神”的边界

文章随后转向边界讨论，避免把 benchmark 领先直接等同于全场景替代。

重点使用：

- Stockfish 优化循环负反馈
- 极难数学任务烧空额度但无答案
- METR 关于数周级 R&D 自动化仍不可靠的评估
- 中文社区对普通 CRUD、中文写作任务的分歧

这一节形成第一层反转：Fable 5 很强，但不是所有任务都值得上 Fable 5。

### 4. 第三层：成本才是普通用户的真实痛点

v1.0 把 token 成本单独展开，而不是作为附属段落处理。

重点使用：

- 官方价格：\$10/M input、\$50/M output
- 单任务成本：200K input + 50K output 约 \$4.50
- 长任务成本：\$20-\$40 per hour
- HN 用户三天 \$4000 session
- OpenCode \$4365.02 session
- 宝玉 \$200 套餐不够用
- 卡兹克 \$200 Max 跑 3 个任务烧空
- 6 月 23 日后 Fable 5 从订阅移除，改为 usage credits

这一节的核心判断是：Fable 5 不是单纯变贵，而是让前沿模型从“互联网会员产品”回到“云计算资源”。

### 5. 第四层：静默降级比贵更严重

v1.0 把 safety classifier / PEFT / steering vectors 相关争议放在成本之后，因为它比价格更隐蔽、更适合作为文章后半段的核心冲突。

重点使用：

- Fable 5 在 cyber / bio / chemistry 查询上可能触发 classifier，回退到 Opus 4.8
- Anthropic 自报触发率低于 5% session
- 社区反馈分类器过度敏感
- “Anthropic won't tell you if your output is being silently nerfed”
- shadow banning 类比
- 用户付 Fable 5 价格，却可能拿到 Opus 4.8 答案

这一节的核心判断是：未来模型竞争不只是能力竞争，也是透明度竞争。

### 6. 第五层：中文圈镜像与工具链回扣

v1.0 在中文圈部分没有只写“怎么薅羊毛”，而是把中转站、虚拟卡、Bedrock、人民币充值等现象解释为一个更大的趋势：

当模型越来越强、越来越贵、越来越不透明，用户自然会需要中间层。

这为后续 007 Agent 工具链文章埋下伏笔：

- 模型越强，越需要工具链。
- 模型越贵，越需要预算控制。
- 模型越不透明，越需要观测层。
- 模型越分层，越需要路由和替代方案。

### 7. 结尾：从模型新闻提升到产业判断

v1.0 的结尾没有停在“Fable 5 很强但很贵”，而是收束为：

Fable 5 不是一次普通模型升级，而是一次 AI 订阅体系调整的预演。

核心收束句：

> 模型封神只是新闻。
>
> 谁能把神请进生产系统里，还不把账单烧穿，才是下一阶段真正的能力。

## 四、与 002 写法的继承关系

002 是“海外教育 AI 增长”的全面调研型文章，最终版本的写法有三个原则：

1. 从圈层文章走向公共内容。
2. 从产品经理腔走向白话叙事。
3. 从作者立场走向读者立场。

006 v1.0 继承了这三点。

### 1. 从圈层文章走向公共内容

v1.0 没有只写给模型发烧友或 benchmark 玩家，而是把问题扩展到所有 AI 使用者：

- 普通用户还用不用得起？
- 开发者该怎么判断成本？
- 创业公司如何面对模型分层？
- 闭源模型静默降级会不会影响产品判断？
- 工具链为什么会变得更重要？

这样处理后，文章从“Fable 5 发布分析”变成“前沿模型商业化拐点分析”。

### 2. 从术语解释走向白话叙事

v1.0 尽量避免直接堆叠 PEFT、steering vectors、safety classifier、usage credits、agentic workflow 等术语，而是用白话解释其影响：

- “你付的是 Fable 5 的价格，但某些任务实际拿到的是 Opus 4.8 的答案。”
- “过去你订阅的是一个 AI 助手，以后你调用的是一台昂贵的智能机器。”
- “Agent 不是一次问答，它会读文件、查资料、写代码、跑测试、改错，再循环。”
- “贵至少是透明的。真正麻烦的是静默降级。”

### 3. 从作者立场走向读者立场

v1.0 虽然保留了“我调研时发现 subagent 误判”的第一手视角，但主体不是写作者经历，而是读者关心的判断：

- 它到底强不强？
- 哪些任务值得用？
- 为什么月卡不够用了？
- 静默降级为什么危险？
- 普通开发者该看见什么趋势？

## 五、v1.0 当前优点

1. **开头有独特性**：subagent 误判不是二手信息，能形成区别于普通模型新闻的入口。
2. **主线清楚**：从“它真的存在”到“它确实很强”，再到“强有边界”“贵有代价”“静默降级更危险”。
3. **热点与长期主线相连**：结尾自然回扣 Agent 工具链，为 007 铺路。
4. **表达相对公共化**：没有过度沉迷 benchmark 细节，也没有只写开发者黑话。
5. **有可传播金句**：如“短任务看能力，长任务看链条”“贵至少是透明的”“模型封神只是新闻”。

---

## 六、v1.0 当前问题

1. **篇幅略长**：作为公众号热点稿，v1.0 信息密度较高，后续 preview 版可压缩 10%-15%。
2. **标题还可更公众号化**：当前标题偏调研报告，可考虑加入“\$200 跑 3 个任务烧空”或“你付 Fable 5 的钱，可能拿 Opus 的答案”这类更强钩子。
3. **数据表缺失**：v1.0 为了阅读流畅没有放 benchmark 表格，但调研型文章可以考虑加入一个不超过 5 列的简表。
4. **中文社区部分还可更具体**：当前更多是趋势归纳，后续可补一两个更有画面感的 V2EX / 宝玉 / 卡兹克案例。
5. **静默降级部分需要把握措辞**：需要避免写成阴谋论，应保持“社区担忧 + 机制风险 + 透明度问题”的表述。

## 七、后续迭代方向

### 1. 标题方向

可测试三个方向：

| 方向 | 候选标题 | 特点 |
|---|---|---|
| 调研型 | `Fable 5 封神了吗：一次发布 24 小时内的全面调研` | 稳健、信息完整 |
| 刺客型 | `\$200 跑 3 个任务烧空后，我重新理解了 Fable 5` | 强传播、强情绪 |
| 不平等型 | `你付 Fable 5 的钱，可能拿到 Opus 的答案` | 抓住静默降级争议 |
| 产业型 | `Fable 5 不是模型升级，是月卡时代的结束` | 判断更高级，适合作为主标题 |

### 2. Preview 版可做的结构优化

1. 开头缩短 20%，更快进入“一句话结论”。
2. benchmark 部分增加小表格，只保留 4-5 个关键指标。
3. 成本部分增加一个“普通用户账本”的具象段落。
4. 静默降级部分减少术语，强化“不告知”的用户体验。
5. 结尾更短，保留两句强收束。

### 3. 可保留的金句

- “封神是真的，但这是一个限定版的封神。”
- “短任务看能力，长任务看链条。”
- “你以为买的是最强，但你真正需要的可能只是够用。”
- “贵至少是透明的。真正麻烦的是静默降级。”
- “过去你订阅的是一个 AI 助手，以后你调用的是一台昂贵的智能机器。”
- “前沿模型正在从互联网会员产品变回云计算资源。”
- “模型越强，越不是终点。模型越贵，越需要工具链。”
- “模型封神只是新闻。谁能把神请进生产系统里，还不把账单烧穿，才是下一阶段真正的能力。”
