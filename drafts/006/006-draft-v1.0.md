# Fable 5 封神了吗：一次发布 24 小时内的全面调研

今天这篇不是模型发布新闻，也不是跟风吹一遍 benchmark。

Fable 5 / Mythos 5 发布后，中文圈很快出现了一个说法：Claude 史上最强模型来了，普通人慎用。这个标题很抓人，因为它同时击中了两个情绪：一个是“又有新王登基了”，另一个是“这东西可能贵到普通人用不起”。

但我真正被触发去调研，不是因为它看起来很强，而是因为我第一轮让 3 路 subagent 分头查证时，它们给了我一个非常一致、也非常错误的结论：

它们都认为 Fable 5 / Mythos 5 很可能不存在。

原因也很简单。它们的知识截止在 2026 年 1 月，看不到 9 个小时前刚发生的模型发布。于是它们会基于已有知识做一个看似严谨的判断：训练数据里没有，官方记忆里没有，历史产品线里没有，所以大概率是虚构信息。

但我用 bb-browser 实际打开 Anthropic 官方页面和英文社区之后，结论反过来了：

Fable 5 真实存在。Mythos 5 也真实存在。Stripe 5000 万行 Ruby 迁移、14 个蛋白靶点里产生 9 个候选、Project Glasswing、Hebbia 金融基准最高分，这些核心信息都能被验证。

唯一没有证据的是“Karpathy 加入 Anthropic”。

这件事本身就很有意思。我们已经习惯把 AI agent 当作信息处理工具，但在真正的热点事件上，agent 的第一反应可能不是“查到了什么”，而是“我看不到，所以它可能不存在”。这也是为什么这篇文章不想只复述发布会，而是想完整回答一个问题：

Fable 5 到底有没有封神？

我的结论是：封神是真的，但这是一个限定版的封神。

它在 coding / agentic 任务上确实全面领先，尤其是复杂工程、前端还原、多轮工具调用这类任务。但真正值得关注的，不只是它变强了，而是它让三件事同时浮出水面：

第一，最强模型开始被分层发售。

第二，月卡时代正在结束，前沿模型会越来越像按量燃烧的云资源。

第三，用户以为自己买的是能力，实际买到的可能是一个会被静默降级、静默限制、静默改写的模型入口。

这才是 Fable 5 最值得写的地方。

## 它确实很强，尤其是在 Agent 任务上

先说强的部分。

从公开 benchmark 看，Fable 5 在软件工程、工具调用、视觉理解、复杂任务自动化上，都是明显的第一梯队，很多项目甚至是断层领先。

SWE-Bench Pro 上，Fable 5 达到 80.3%，而 Opus 4.8 是 69.2%，领先 11.1 个百分点。SWE-Bench Verified 上，Fable 5 是 95.0%，Opus 4.8 是 88.6%。FrontierCode Diamond 上，Fable 5 是 29.3%，Opus 4.8 是 13.4%，GPT-5.5 是 5.7%。

这些数字不用过度解读，已经足够说明问题：如果你的任务是写代码、改代码、跑复杂工程任务、接工具链完成长流程，Fable 5 不是小升级，而是一次明显跨越。

这也解释了为什么英文社区里第一批开发者的反应会很兴奋。

Simon Willison 在 HN 上的评价很直接：他已经在 Claude Code 里花了足够时间，结论是“it's a beast”。他把一些自己拖了几个月的难题扔给它，Fable 5 能相当顺畅地推进。

另一个用户提到，高 effort 下跑两个大重构，没有很快撞到 context 上限，感觉它更聪明，也更少在原地打转消耗 token。还有用户说，Fable 5 用 30 分钟完成了 Opus 4.8 和 ChatGPT Codex 5.5 都没解出来的逆向工程题。

更典型的是前端和 UI 场景。Canva 评测负责人 dannyw 的说法是，Fable 5 在前端 / UI 设计上是一个 immediate jump，生成结果 delightful without feeling like AI vibe coded。中文 V2EX 里也有人把 Figma 设计稿直接丢给 Fable 5 做前端还原，评价是 1:1 像素级还原，爆杀 5.5。

这类反馈很关键，因为它说明 Fable 5 的进步不是“更会聊天”，而是“更会干活”。

过去我们评价模型，经常说它更聪明、更会推理、更懂上下文。但到了 Fable 5 这一代，真正的差异开始出现在任务完成链条里：它能不能看懂一个复杂项目，能不能持续调用工具，能不能改完代码后自己验证，能不能少走弯路，能不能在多轮任务里保持方向感。

这就是为什么我更愿意把 Fable 5 看成一个 agentic model，而不是一个普通聊天模型。

它强的地方，不是回答问题，而是推进工作。

## 但“封神”有边界

问题在于，Fable 5 的强不是无条件的。

英文社区的正反馈很多，但负反馈也同样具体。

有人拿它做 Stockfish 优化循环，结果发现它无法恢复近期优化，不如 Opus 4.8 有创造力。有人拿它做极难数学题，结果直接烧穿额度，最后也没有明显答案。METR 的第三方评估也指出，Mythos 5 仍然 likely unable to fully and reliably automate R&D for frontier projects spanning multiple weeks。

这句话翻译成白话就是：它已经很强，但还不能稳定地替你完成跨数周的前沿研发项目。

这很重要。

今天很多模型发布最容易制造的错觉，是把 benchmark 领先等同于“所有复杂任务都能自动完成”。但真实使用里，agent 任务有一个残酷特点：越长，越容易暴露稳定性问题。

短任务看能力，长任务看链条。

一个模型可以在 30 分钟里显得神勇，但到了 3 小时、3 天、3 周，问题就变成了：它会不会偏航？会不会重复劳动？会不会误判需求？会不会越改越乱？会不会在中间某一步把前面的约束忘掉？会不会把 token 烧光但没有实质进展？

所以 Fable 5 的“封神”，更准确地说，是在一类任务上封神：复杂但边界相对清楚的 coding / agentic / UI / 工程自动化任务。

它还不是一个稳定接管数周级研发项目的自动员工。

中文社区的分歧也指向同一个结论。

有人觉得它已经可以当主力模型，有人觉得它分析技术方案能找出不少问题。但也有人说，写文章感觉不如 Opus，AI 味更浓。还有人说，写个 CRUD 用得着这么高级的模型吗，普通模型完全够用。

这不是社区不懂模型，而是使用场景不同。

如果你拿 Fable 5 做高复杂度工程，它的优势会很明显。如果你只是让它写普通业务代码、做日常问答、写中文内容，它的边际收益可能没有价格涨幅那么明显。

这也是普通用户最容易踩坑的地方：你以为买的是“最强”，但你真正需要的可能只是“够用”。

## 真正的刺客不是价格，而是长任务

Fable 5 的官方 API 价格是每百万 input token 10 美元、每百万 output token 50 美元，大约是 Opus 4.8 的 2 倍。

单看这个价格，很多人会觉得还好。一个 200K input + 50K output 的任务，Fable 5 大约是 4.50 美元。如果启用 90% prompt-cache，成本可以降到 2.70 美元左右，只比 Opus 4.8 贵 0.45 美元。

但这只是静态账本。

真正的问题发生在 long-running agent loop 里。

Agent 不是一次问答。它会读文件、查资料、写代码、跑测试、改错、再读文件、再写代码、再跑测试。只要循环跑起来，token 消耗就不是线性增长，而是像水龙头没关一样持续流出。

社区里已经出现了非常夸张的账单。

HN 上有人提到，一个 Opus session 三天烧了 4000 美元。OpenCode session 里也出现过 4365.02 美元的实时显示。Lushbinary 的观察是，Fable 5 在 Cursor 这类 long-running agent loop 里连续跑时，token 燃烧容易达到每小时 20 到 40 美元。

中文圈的体感更直接。

宝玉的原话是：Fable 5 真的消耗流量超快，我刚升级了 200 美元的套餐，根本不够用。卡兹克的说法更夸张：200 美元 Claude Max 会员，跑了 3 个任务，其中一个还没跑完，直接就干没了。

这就是为什么 Fable 5 的发布，不只是一次模型升级，而是一次用户心理账本的重置。

过去的订阅制给用户一种错觉：我每月付 20 美元、100 美元、200 美元，就可以买到某种“无限接近无限”的使用权。哪怕平台有速率限制，用户心里仍然觉得自己买的是月卡。

但 Fable 5 把这种幻觉打破了。

6 月 23 日之后，Fable 5 将从 Pro / Max / Team / Enterprise 订阅中移除，继续使用需要 usage credits。也就是说，用户不再是买一张月卡，然后在心理上尽量多用；而是每一次调用都要重新感知成本。

这背后是一个大趋势：前沿模型正在从“互联网会员产品”变回“云计算资源”。

以前你订阅的是一个 AI 助手。

以后你调用的是一台昂贵的智能机器。

这两个东西的商业逻辑完全不同。

## 静默降级，才是真正的不平等

如果只是贵，其实还不算最严重。

贵至少是透明的。你知道价格，你可以选择用或者不用。你可以在高价值任务上调用 Fable 5，在普通任务上切回便宜模型。你可以做缓存、做路由、做预算控制。

真正麻烦的是静默降级。

Fable 5 和 Mythos 5 的关系，很像同一套能力在不同安全边界下的两个版本。公开面向普通用户的是 Fable 5；Mythos 5 是更受限、更高能力、只开放给部分合作伙伴的版本。

在一些 cyber / bio / chemistry 查询上，Fable 5 会触发 safety classifier，然后回退到 Opus 4.8。Anthropic 自报触发率低于 5% session，但社区反馈里，对这个分类器“过度敏感”的吐槽非常多。有人提到实验室自动化、健美研究、MRI 脑分割、蚊子疟疾都可能触发限制。

这里不讨论这些限制本身是否合理。更关键的问题是：用户是否知道自己正在被降级？

如果你付的是 Fable 5 的价格，但某些任务实际拿到的是 Opus 4.8 的答案，而且系统没有明确告诉你，这就是信息不对称。

这也是英文社区争议最大的地方。

HN 上有人把这种机制类比成社交平台的 shadow banning。不是直接告诉你“这不允许”，而是不声不响地改变你的问题、改变你的回答，甚至降低模型能力。HN moderator 也提到一个核心问题：Anthropic won't tell you if your output is being silently nerfed。

这句话比所有 benchmark 都更值得警惕。

因为它意味着，未来模型竞争不只是能力竞争，也是透明度竞争。

用户真正害怕的，不是模型说“我不能做这个”。用户真正害怕的是，模型看起来正常工作，但实际上已经换了脑子，降了能力，改了输出，而你不知道。

这会影响开发者的判断。你可能以为是自己 prompt 写得不好，可能以为是任务本身太难，可能以为是模型能力退化，甚至可能错误地调整整个产品路线。但真实原因可能只是某个看不见的分类器触发了。

这才是 Fable 5 事件里最值得长期关注的地方。

不是“最强模型给不给所有人用”，而是“当它不给你完整能力时，会不会告诉你”。

## 中文圈看到的是另一层问题

英文社区关心的是能力、账单和安全边界。中文开发者还会多一层现实问题：怎么用得上，怎么用得起。

从调研看，中文圈很快出现了几条路径。

一类是第三方中转站，比如 APIYI、赞 AI、OpenRouter、AnySearch、Cubence 这类服务，卖点是人民币充值、折扣、转发官方资源。

一类是虚拟卡加官方账号，比如 WildCard / Depay 这类路径。

还有一类是云平台，比如 AWS Bedrock。V2EX 上有人提醒，Fable 既然上了 Bedrock，那些云 MaaS 路径大概率不会下。

这些讨论看起来像“薅羊毛”，但背后其实是另一个信号：当模型能力越来越强、价格越来越高、订阅越来越不稳定，用户会自然寻找中间层。

中转站、云平台、代理层、模型路由、预算控制、缓存系统，都会变得更重要。

因为单个用户已经很难直接面对前沿模型的复杂商业规则。什么时候有订阅，什么时候改 usage credits，什么时候触发降级，什么时候被限流，什么时候涨价，什么时候某个国家或地区访问受限，普通开发者没有能力逐一处理。

于是新的需求出现了：谁能把前沿模型包装成可用、可控、可预算、可切换的生产力工具？

这其实也呼应了我之前一直关注的 Agent 工具链问题。

模型越强，越不是终点。模型越贵，越需要工具链。模型越不透明，越需要观测层。模型越分层，越需要路由和替代方案。

Fable 5 不是让工具链变得不重要，而是让工具链变得更重要了。

## 这不是一次模型升级，而是一次订阅体系调整

APPSO 的一句话很准确：Fable 5 的发布，与其说是一次模型升级，倒不如说是一次彻底调整 AI 订阅体系的预热。

我同意这个判断。

如果只看能力，Fable 5 的故事会被写成：Claude 又变强了，coding 更强了，agent 更强了，前端更强了，benchmark 又刷新了。

但如果把定价、订阅、分层发售、安全分类器、静默降级、社区账单放在一起看，它更像一个行业拐点：

前沿模型不再假装自己是普通消费级软件。

它开始回到自己的真实形态：昂贵、稀缺、分层、按量计费、对不同用户开放不同能力。

过去一年，很多人已经习惯了一个窗口期：每月几十美元，就能使用接近前沿的模型能力。这个窗口期让大量个人开发者、独立创作者、小团队获得了前所未有的杠杆。

但 Fable 5 之后，这个窗口期可能开始收窄。

不是说普通人不能用 AI 了，而是“最前沿能力随便用”的时代正在结束。越强的模型，越不可能直接扔给所有人。越接近科研、工程、自动化和高风险领域，模型越会被拆成不同版本、不同价格、不同安全边界、不同可用范围。

这对用户不是纯坏事。强模型本来就贵，平台不可能长期用月卡补贴无限调用。按量计费可以让资源分配更真实，也可以让高价值任务得到更稳定的供给。

但它会改变生态。

个人用户会更谨慎。开发者会更重视成本控制。创业公司会重新计算毛利。Agent 产品会被迫设计预算上限。模型中间层会变得更有价值。开源模型会因为“可控”和“透明”重新获得吸引力。

digitaltrees 为 propelcode.app 转向 3 台 512GB Mac Studio 跑开源模型，不一定是主流选择，但它代表一种情绪：如果闭源模型越来越强、越来越贵、越来越不透明，总会有人选择把能力拿回自己手里。

这就是 Fable 5 发布真正释放的信号。

它告诉我们，AI 的下一阶段不是所有人都无差别享受最强模型，而是不同人、不同组织、不同预算，接入不同层级的智能。

## Fable 5 封神了吗？

最后回到标题。

Fable 5 封神了吗？

如果你问的是 coding benchmark，它封了。

如果你问的是 agentic workflow，它很接近。

如果你问的是前端还原、复杂工程、长上下文工具使用，它确实是一次非常明显的跃迁。

但如果你问的是普通用户能不能放心无脑用，答案是否定的。

如果你问的是它能不能稳定接管数周级研发项目，答案也是否定的。

如果你问的是你付了 Fable 5 的钱，就一定能拿到 Fable 5 的完整能力，答案更是否定的。

所以，Fable 5 的真实位置不是“神降临了”。

它更像一个分水岭。

在它之前，很多人还相信 AI 前沿能力会以月卡形式持续普惠。只要每月付一笔钱，就能站在大模型能力的最前沿。

在它之后，我们要开始接受另一个现实：最强能力会越来越贵，越来越分层，越来越按量计费，也越来越需要工具链来管理。

这篇调研最后留给我的不是兴奋，而是一个更实际的判断：

未来真正有价值的，不只是会调用最强模型的人，而是能把强模型、便宜模型、开源模型、中转服务、缓存、预算、评测和降级监控组织成一套稳定工作流的人。

模型封神只是新闻。

谁能把神请进生产系统里，还不把账单烧穿，才是下一阶段真正的能力。
