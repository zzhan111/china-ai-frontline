原创 之哲 [UIEVENTS事历]

Bun 的创始人 Jarred Sumner 做了一场没有 PPT 的演讲。

他在台上打开终端，没有念稿，没有切幻灯片。台下的人看着他一行一行跑命令，看到的不再是"AI 帮你写代码"的演示——而是一个完整的开发流程在自动运转。

有人提了一个 bug，Agent 收到之后自己动手：

**1. 读 issue，在本地把 bug 复现出来。**
**2. 写一个失败的测试用例，把 bug 锁死。**
**3. 修改代码，让测试通过。**
**4. 自动生成 PR，带描述。**
**5. 读自己写的 diff，做 review。**
**6. 根据 review 反馈再改一版，merge。**

六步。从 bug 报告到 commit 合并，全程没有人碰键盘。

这不是 AI 辅助编程。这是 Agent 独立完成了一个开发者的完整工作步骤。

演讲之后，Claude 推出了 Dynamic Workflows——把 Jarred 演示的东西做成了可安装的 slash command，修 bug 全流程一键触发。社区紧跟着出现了十几个模仿项目。但这不是我要讲的重点。

重点是：这场演讲回答了一个比"Agent 能不能写代码"更底层的问题——Agent 能不能作为独立的生产者干活？答案是：能。而且 2025 年末这个答案就已经在台前被验证了。

光能干活还不够。一个人会写代码不代表他在经济里是完整的——

**他还需要把劳动成果卖出去，**
**或者买到别人的。**

工厂能生产不代表它嵌入了经济，它还需要货币、市场、定价机制。Agent 也一样。

## 01

1999 年，HTTP 协议预留了一个状态码，叫 **402 Payment Required**。

设计者的想法是：未来的互联网，付费应该嵌在 HTTP 往返里。用户发请求，服务器回一句"你先付钱"，用户在同一轮交互中转账，服务器吐数据。

但这个设想在当时没法落地。信用卡支付需要独立的网关、第三方清算、层层中介——不可能塞进一个 HTTP 往返。402 在规范里躺了 25 年，几乎没人碰过。

直到加密支付出现。

2025 年，Coinbase 内部孵化了一个协议叫 x402。机制：客户端发请求 → 服务端返回 402 + 支付要求（USDC 稳定币）→ 客户端链上付 → 服务端验证 → 返回数据。整个支付流程嵌在一次 HTTP 往返里——没有中介、不需要信用卡、不需要 Stripe、不需要 KYC。

2026 年上半年，x402 从 Coinbase 独立出来，成立了 x402 基金会。同一时间，一个叫 HermesHub 的社区项目用 x402 做了一个 Creator Marketplace。

这个 marketplace 的规则：一个 skill 作者写了一个 Agent 技能——比如"公众号标题生成"、"法务类案检索"、"API 自动搭建"——

**上传到 HermesHub。**
**这个技能 Hermes Agent 想用，就付一笔钱，0.01 USDC 起。**

付款是链上的，验收通过后拿 license key。

到账多少？**95% 直接打进作者的加密钱包。**

作为对比：App Store 给开发者 70%（年收入 100 万美元以下 85%，但大部分独立开发者面对的是 70%），Stripe 每笔抽 2.9% + 0.3 美元。在这里，没有平台抽成，没有支付渠道费，没有中间人。

HermesHub 目前还很小——只有 22 个 skill。网上有人声称它有 691 个，实际差了两个数量级。但这 22 个 skill 不是重点。重点是它证明了一个可能性：Agent 的技能可以作为独立定价、独立分发的经济资产存在。

而 x402 生态本身已经有了不少安静运转的证据。根据 x402scan 的实时数据，过去 30 天有超过 500 万笔 x402 交易、约 120 万美元的交易量、近 15 万买家。协议级别已经过了"零"的验证。只是还没有人把它讲成一个故事。

## 02

现在把这两个信号放在一起。

Jarred 演示的东西回答的是：**Agent 能不能自己干活？能。** 6 步闭环，2025 年末在台上跑完了。

x402 + HermesHub 回答的是：**Agent 产出的技能能不能自己赚钱？能。** 链上付费，零中介，95% payout。

一个解决了生产端。一个解决了流通端。

这两件事单独看，都不像"大新闻"。一个开发者演讲，一个冷门状态码。但放在一起，它们拼出来的是 Agent 经济的完整回路。

这件事和"模型又强了多少"、"benchmark 又刷了多少分"不是同一个层次的问题。模型更强解决的是能力上限。经济回路闭合解决的是 Agent 能不能脱离人的中转站自己运转。

工厂再大，东西卖不出去，它只是一个车间，不是一个经济体。

## 03

当下是 2026 年 6 月。Jarred 的演讲在 2025 年末，x402 的基金会搬迁在 2026 上半年。它们发生在不同的时间、不同的平台、由完全无关的团队推进。不是同一家公司布的局，不是同一个圈子的热门话题。

但当两个独立信号指向同一张拼图，它就不是孤例。

**它说明一件事：Agent 正在从"能做什么"进入"靠什么运转"。**

能做什么，是技术故事。靠什么运转，是经济故事。技术故事一直在讲——GPT-4 到 Claude 5，coding benchmark 到长上下文推理，每季度都有新模型出来刷榜。经济故事讲的是另一套东西：定价、交易、流通、激励。这些和模型能力无关，和基础设施有关。

Jarred 的 workflow 和 x402 的 marketplace，刚好是这条基础设施的两根支柱。

## 04

如果你是一个独立开发者或 indie maker，这一节是写给你的。

假设你手里有一个 Agent skill——它可能是一个帮你写爆款标题的 prompt 模板，一个法律案例检索的 workflow，或者本地脚本帮你一键生成 PPT。在传统的分发路径下，你要么把它做成一个 SaaS 产品（需要前后端、支付接入、用户系统），要么上架 App Store 等审核，要么接 Stripe 填银行信息。

现在有一条不一样的路：把你这个 skill 的 SKILL.md 和 references 打包，上传到 HermesHub（或者未来任何一个兼容 x402 的 marketplace），设定一个价格——0.01 USDC 起。

**Agent 发现了，付了钱，就能用。**

你拿 95%，零中介。不需要营业执照，不需要公司主体，不需要 KYC。

这条路现在显然不成熟——22 个 skill 的 marketplace，买家群体还只是早期探索者。但这不重要。重要的是，它第一次让"Agent skill 创作者"和"直接拿钱"这两件事之间，不需要任何一个平台型公司。

这和 2008 年 App Store 刚开的时候不一样。那时候你只能等苹果建商店。这一次，基础设施的搭建者和技能创作者，是同步在发现这个经济能长多大的。

## 05

说实话的部分。

x402 生态目前确实很薄。22 个 skill 和 App Store 百万应用之间差了几个数量级。加密支付对普通用户的摩擦仍然很高——大多数人不持有 USDC，不习惯"签名即付款"的交互。这个摩擦不是一篇文章能解决的。

Jarred 的 workflow 目前只在编程场景被充分验证。Agent 能不能在写作、法律分析、设计稿交付这些领域做到同样的"全流程独立交付"，还没有足够的案例。

这些判断的保质期：以 2026 年 6 月的基准来看，大概率 6 到 12 个月内它们就会被更清晰的数据验证或推翻。也许 x402 社区没等到生态爆发就失去了 momentum。也许 Jarred 的 workflow 范式被大厂吸收后变成另一个名字，不再是独立的叙事。

但这些不确定性不影响一个核心判断：

**Agent 干活和 Agent 赚钱，这两件事的基础设施是在搭的，而且已经过了"零"的阶段。**
