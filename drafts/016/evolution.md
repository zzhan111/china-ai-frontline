- **"step change" 类文章的写作纪律**：被一个流行的英文判断（Hacker News 351p + 国际知名分析师）吸引时，第一件事不是跟着写"对，step change"，而是把它拆成"账本 / 机制 / 体验"三层证据逐层验证。账本层（价格 5.7x）数据 100% 站得住；机制层（能力追平）数据 70% 站得住；体验层（社区反应）数据 80% 站得住——综合判断"部分真"，不是"全真"。

## 2026-06-27 — preview.md 生成 + 格式修正

### 做了什么

1. 从 v1.4（94.2/100）生成 preview.md（公众号发布版）
2. 改动：删除元信息、引用体系转换（URL → 编号）、开头重写（事件 → 场景+事件）、结构压缩（5段 → 4段）、数据精简（表格 → 散文）
3. **回撤**：`**01**` → `## 一`。原因见下方教训。

### 学到什么

**preview.md 应保留 markdown 原生 `##` 格式，不使用公众号 `**01**` 格式。**

理由：
- preview.md 是仓库内的源文件，不是公众号编辑器的最终渲染
- `##` → `**01**` 是公众号编辑器的排版步骤，应在发布时由人工完成，不应写入源文件
- `##` 在 markdown 中有明确的层级语义（H2），转为纯加粗后丢失了这一信息
- 如果将来需要从 preview.md 重新生成其他平台版本（Substack / X thread / 小红书），`##` 可以自动转换，`**01**` 不能

**写入文档防止重复**：本教训已记录在此 evolution.md 条目中。后续所有 draft → preview 转换应遵循此规则。
