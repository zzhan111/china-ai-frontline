群里几个做跨境电商和独立站的，困境高度一致：AI 写文案、生图已经稳定了（亚马逊 listing 文案+主副图+详情页全链路跑通），但卡在"最后一公里"——没有 API 把内容推上去。

对话暴露了三个共识：
- **API 不平等**：硅谷公司（Twitter、Cloudflare、Google、Amazon SP-API）主动开放 API，中国平台（阿里国际站、1688、京东、小红书）封闭。不是技术问题，是信任问题——"万一你为非作歹怎么办"。
- **浏览器自动化是死胡同**：各家反爬机制不断升级，图形界面对大模型太绕，token 消耗大、不稳定。
- **终极愿景**是"文字 AI 组织，工作 AI 推"——agent 从生成到执行全链路闭环。

我的方案在群里引发了强烈兴趣：browse.sh（400+ 站点内部 API 端点集合）→ 翻译到 bb-browser 本地适配器 → 0 token CDP 调用。群里有人立刻去研究，有人要了我的 PR #79 链接。这说明痛点真实、方案有需求。

这其实是 **"API 不平等"时代的 agent 基础设施**：既然平台不给 API，agent 就通过浏览器自己"长"出 API。不是爬 HTML，是直接调到站点内部接口——和官方 API 等效，但不需要申请。

## 2026-05-28 15:30

来源：准备一篇人物访谈选题的实操过程

做人物访谈，准备问题集有一套可复用的工作流，这次跑通了一遍，值得记下来。

**核心发现：好问题不是"想出来"的，是"读出来"的。**

传统方式：拿到访谈对象背景 → 脑暴问题 → 发给对方。结果：问题浮在表面，对方给套话。

这次的做法：先把能找到的一手材料全部读完（本人写的文章、公开项目介绍、简历或公开履历），然后不急着写问题，而是先找"缝"——那些材料之间**对不上、说不通、或者太有张力**的地方。缝才是访谈真正该钻进去的地方。

找到缝之后，做一次"校准"：跟自己（或委托方）确认几件事——最想钻哪几条缝？调性要共情侧写还是追问核实？访谈形式（单次/多次/异步）？署名方式？这四件事决定问题集的体量、措辞、追问力度。

校准完，再写问题——每个问题必须扎在被访者**真实说过的话或做过的事**上，不能悬空。问题按叙事弧排序，分 block，标★必问项，附现场追问锦囊（"能举个具体例子吗 / 那一刻你心里在想什么 / 后来呢"）。

**"缝"的识别模式（可泛化）：**
- 公开展示的身份 vs 私下表达的状态，反差在哪
- 技术主张 vs 资源约束，是信仰还是被逼出来的现实
- 对外讲的"机会"vs 内部叫的阶段名，死过几次
- 简历上的时间线/规模 vs 他自己文章里的语气，两者是否咬合

最后：用他**自己文章里的原话、他自己的项目名字**去搭问题，被访者会感受到"你认真读过我写的东西"——这是访谈建立信任的最快路径，比任何暖场都管用。

- 判断是否值得升级成长文（"如何用 AI 准备一场人物访谈"方法论长文）
