## 2026-06-02 Coze 3.0 直播观感

首发平台：待定
audience：AI builder + 关注国内 AI 产品 PMF 的从业者

看了 Coze 3.0 直播。最打动我的不是技术参数，而是产品定位的直觉对了。

真正面对大众市场的 AI 产品，特征不是参数最大、模型最新，而是三个词：**低技术门槛、好泛化、真实工作场景**。

Coze 3.0 的 skill store 里充斥着这样的技能包：

- **法务类案生成**：输入案情摘要，输出类案检索报告
- **公众号爆款写作**：给素材，按爆款结构出排版好的文章
- **金融市场分析**：自然语言描述标的需求，输出研报摘要 + 数据可视化

这些 skill 的共同点：
1. 用户**不用写代码**——没有 prompt engineering，没有 API 调优
2. **不用从零找脚手架**——技能包预装，即开即用
3. **自然语言就够了**——用"帮我写一个……"替代写 prompt 模板
4. 每个 skill 锚定一个**真实岗位的真实痛点**——不是"AI 能做什么"，而是"我的工作卡在哪"

这不只是"AI 降低门槛"，这是 **PMF 的落地路径变了**：

- 第一波（2023-2024）：模型能力展示 → "看，它能写诗！" → 没有工作流嵌入
- 第二波（2024-2025）：Agent 框架 → "你可以搭一个 workflow" → 需要技术理解
- 第三波（2026-）：Skill 商店 → "你的工作，帮你做完" → 零技术假设

Coze 3.0 让我重新想一个问题：**在一个产品里，模型能力是基础设施，不是卖点。卖点是"打开就能替我做一部分工作"。**

这和 china-ai-frontline 做 domain-specific skill 的直觉一致——只不过 Coze 的平台化路径是让用户发现/安装 skill，我们做的是为特定内容工作者定制化。殊途同归。

另外注意到一个细节：Coze 3.0 的 skill 大多不是"通用 AI 能力"，而是"行业 knowledge + AI 执行"的封装。法务 skill 不只是调用 LLM，而是内置了类案检索的检索策略、裁判要旨的提取模板、判决书结构的知识。**Know-how 在 skill 里，不在用户的 prompt 里。**

这可能是国内 AI 产品走向 PMF 的关键转折。

## 2026-06-03 Coze skill → 本地 agent 反哺路径调研

来源：inbox/2026-06.md#2026-06-02-14-30（Coze 3.0 直播观感延伸）

**核心问题**：Coze 上的行业 skill（法务类案、公众号爆款、金融研报）能否移植到 OpenClaw / Hermes，让本地 agent 不用从零搭 workflow？

**调研结论**：分四类反哺路径，技术可行性递减。

### 路径 A：直接 fork skill 仓库（可行，难度低）

Coze 3.0 的 skill 大多开放源码或导出 JSON 定义。
- ✅ 法务类案 skill：本质是 prompt 模板 + 检索策略 → 可平移成 references/ 类案检索.md
- ✅ 公众号爆款 skill：标题模板 + 段落结构 + 排版规则 → 可平移成 draft-content skill 的子模块
- ✅ 金融研报 skill：分析师 prompt + 数据源 API → 可平移成 references/ 研报结构.md
- 难点：Coze skill 假设了字节内部工具链（豆包/飞书），需要剥离后才能在本地 agent 跑

### 路径 B：MCP 协议桥接（可行，难度中）

Coze 3.0 已支持 MCP server 暴露。
- 本地 agent（Hermes / OpenClaw）通过 `.mcp.json` 订阅 Coze 暴露的行业 skill
- 调用模式：本地 user query → 本地 agent 决策 → MCP call → Coze skill 回答
- 限制：每次调用消耗 Coze 平台 token / 算力 + 延迟 + 网络
- 适用：偶发性专业咨询（"帮我审一份合同"），不适合日常高频操作

### 路径 C：skill 知识蒸馏后离线部署（可行，难度高，价值最大）

把 Coze skill 的 prompt + 检索策略 + 知识库 → 蒸馏成本地 SKILL.md + references/。
- 这正是昨天调研的"领域垂直 agent"路径，Coze 帮我们做了"知识发现"工作
- 步骤：clone Coze 公开 skill → 拆解 prompt 结构 → 改写为 SKILL.md 路由表 → 喂入 references/
- 价值：本地 agent 永久拥有该能力，无外部依赖，无 token 成本
- 案例：Coze 上的"法务类案生成" skill 可蒸馏成本地 hermes-lawyer skill

### 路径 D：行业 know-how 反向沉淀（不可行但值得借鉴）

Coze 上沉淀的行业 know-how（裁判要旨提取模板、研报结构、爆款节奏），
无法直接复制到本地 agent，但**写作框架**可借鉴。
- 启示：Coze skill 的"行业 knowledge + AI 执行"封装思路，与本地 agent 的 SKILL 模式高度同构
- 未来：行业 know-how 本身可能成为稀缺商品，agent 平台之间的差异在"行业 know-how 库"

### 三个判断

1. **路径 C 是最大价值**——把 Coze 当"行业 skill 发现引擎"，蒸馏成本地资产
2. **路径 B 适合早期探索**——MCP 桥接快速验证 skill 价值，再决定是否蒸馏
3. **路径 A 是快速 win**——开源 skill 直接 fork，零成本补齐本地能力

**对 OpenClaw / Hermes 的具体动作建议**：
- 选 1 个 Coze 高 star skill（如金融研报）跑路径 A demo
- 把 demo 流程（clone → 拆解 → 改写 → 装入）写进 `china-ai-frontline/posts/` 作技术内容
- 跑通后把"Coze 行业 skill 蒸馏模板"存为 shared skill（~/.shared-skills/）

## 2026-06-03 Coze × 本地 agent 协作模式探索

来源：inbox/2026-06.md#2026-06-02-14-30（Coze 3.0 直播观感延伸）

**核心问题**：能否让 Coze 类 cloud agent 当"行业专家层"（懂法务、懂金融），执行层调本地 agent（文件读写、浏览器操作、代码执行）——cloud 出 know-how，本地出行动力？

**架构图（脑内）**：

```
[用户 Slack/微信 query]
     ↓
[本地入口 agent (OpenClaw/Hermes)]
     ↓ 判断：需要专业能力
     ↓
     ├── 简单任务 → 本地 SKILL 直接处理（路由式 references/）
     └── 专业任务 → Coze MCP bridge 调用行业 skill
              ↓
              ├── 答案 + 引用 + 证据
              ↓
         [本地 agent 执行后续]
              ↓
              ├── 写到 inbox/drafts/
              ├── 推到 PR
              ├── 发朋友圈
              └── 任何本地能做的动作
```

### 三种协作模式对比

| 模式 | Cloud agent 角色 | Local agent 角色 | 适用场景 |
|---|---|---|---|
| **B1: Cloud 答 + Local 做** | 行业问答（"这份合同有什么风险"） | 接收答案 + 写文件/发推送/做后续动作 | 偶发专业咨询 |
| **B2: Local 问 + Cloud 查** | 知识检索（"近 3 年同类案判决"） | 拆解 query + 拼装 prompt + 跑后续流程 | 高频研究类工作流 |
| **B3: Local 串 + Cloud 评** | 质量审核（"这段话像不像 AI 写的"） | 内容生成主流程 | 内容创作 pipeline |

### 已有技术组件

- **MCP 协议**：Anthropic 2024-11 开源，Coze 3.0 已支持，Claude Code 客户端原生支持
- **Message platform 桥**：Coze bot 可发布到飞书/微信，Hermes Gateway 可桥接 Slack/Discord
- **Skill 描述协议**：Coze skill 的 JSON 定义与 Claude Code SKILL.md frontmatter 高度同构

### 三个关键卡点

1. **延迟**：本地 agent → Coze MCP → 字节算力 → 返回结果，单跳 2-5 秒
   - 解决：本地 agent 异步处理，用户感知不到
2. **成本**：Coze 调用按 token 计费，高频任务成本爆炸
   - 解决：低频走 Coze，高频蒸馏成本地 SKILL（回到路径 C）
3. **数据隐私**：法务/医疗类问题上传到 Coze 平台
   - 解决：本地敏感数据走本地 skill，仅在脱敏 query 时调 Coze

### 与 Reasonix / Hermes 现有架构的关系

- **OpenClaw** (18789): 已经能调外部 API，是天然的 bridge layer
- **Hermes Gateway** (8642): 已支持多 message platform，可作 Coze bot 与本地 agent 间的消息路由
- **Reasonix** (cache-first loop): 适合做"高频 know-how 缓存层"——Coze 答案首次落本地，后续直接读 cache

**不是替代，是分层**：
- Coze 平台 = 行业 know-how 集市（高频更新、用户共创、按调用付费）
- 本地 agent = 个人能力基础设施（隐私、低延迟、永久资产）
- Bridge = 双向 sync 层（按需调用 + 离线蒸馏）

### 一个具体场景

**跨境电商法务咨询**：
1. 用户 Slack 问："这个 Amazon 卖家合同有坑吗？"
2. Hermes Gateway 收到 → 转 OpenClaw
3. OpenClaw 判断：需要法务能力 → Coze MCP bridge
4. Coze "法务类案" skill 返回风险点 + 类似案例 + 建议条款
5. OpenClaw 写 `drafts/contract-review-{date}.md`
6. Hermes Gateway 推 Slack 给用户 + 提交 PR 到 china-ai-frontline
7. 用户在 Slack 回复 "👍" → 走 express lane commit

整个流程对用户是无感的——他只看到"我问了，agent 答了，文件存了"。

## 2026-06-03 Coze 3.0 产品观念映射分析

来源：inbox/2026-06.md#2026-06-02-14-30（Coze 3.0 直播观感）

**核心问题**：Coze 3.0 反映的市场需求和产品观念是什么？对一个工具型 agent（openclaw/hermes/reasonix）来说，平台终局是吃掉我们，还是互补共存？

### Coze 3.0 在卖什么（不是技术参数）

三个关键词：**低技术门槛、好泛化、真实工作场景**。

- 不卖"我们的模型多大"
- 卖"打开就能替我做一部分工作"
- 模型能力是基础设施，不是卖点

这是 B 端用户要的东西——"帮我做完一件事"，不是"给我 AI"。

### 平台经济学的两阶段判断

**短期（1-2 年）：平台 + 工具型 agent 互补**

平台做：行业 skill 集市 + 用户共创 + 按调用付费
工具型 agent 做：个人工作流 + 隐私数据 + 长期资产沉淀

理由：
- 平台擅长"广度"（千万用户、千万场景），不擅长"个人化深度"
- 工具型 agent 擅长"个人流"，不擅长"行业 know-how 库"
- 用户既需要 100 个行业 skill 偶尔调用，也需要 1 个深度适配自己工作流的本地 agent

**长期（3-5 年）：终局被吃掉的风险点**

风险 1：平台下沉到个人 agent 层
- 字节有豆包 + 飞书 + Coze + 抖音 → 全栈打通
- 个人工作流被平台化（"你的工作流在飞书里"）
- 本地 agent 退化为"平台 API 的薄封装"

风险 2：行业 know-how 库成为稀缺资源
- 平台凭用户量沉淀的 know-how 库，个人无法追赶
- Coze skill store 形成"行业最佳实践网络效应"
- 本地 agent 的"个人 know-how"价值相对缩小

风险 3：本地算力成本无法与云端竞争
- 1M context 长文本推理在云端 GPU 上效率 5-10 倍于本地
- 本地 agent 只能依赖本地小模型或购买云端算力 → 又被平台化

### 为什么工具型 agent 还有机会

**个人 agent 的不可替代性**：

1. **隐私与合规**：法务、医疗、财务数据不能上云
2. **延迟与离线**：本地 agent 不依赖网络，断网仍可用
3. **个性化深度**：用户用 6 个月训练出来的 workflow，比平台通用 skill 强 10 倍
4. **跨平台资产**：本地 agent 沉淀的 skill 是用户资产，不被任何平台锁定
5. **创作主权**：内容创作者不愿把"未发布草稿"放在云端

**平台吃掉的是"通用"部分，个人 agent 守住的是"个性"部分**。

### 对 OpenClaw / Hermes / Reasonix 的具体含义

| 项目 | 平台威胁 | 机会 | 战略建议 |
|---|---|---|---|
| **OpenClaw** | 字节全栈下沉 | 个人 API 编排仍稀缺 | 深耕"个人 API 编排"差异化，不做平台化 |
| **Hermes** | 平台自带 message platform | 跨平台 message 桥是稀缺品 | 守住"个人跨平台通信中枢"定位 |
| **Reasonix** | 云端长 context 推理更便宜 | cache + 隐私 + 离线 | 主打"本地 cache 永久资产"，不与云端拼算力 |

**三个战略动作**：

1. **不做通用平台**——平台战争是字节腾讯阿里的事，工具型 agent 做了也输
2. **深耕个人深度**——workflow 个性化是平台不愿做的（千人千面没规模效应）
3. **强化资产沉淀**——用户的 skill / knowledge / context 是个人资产，本地 agent 是唯一可信的"保险柜"

### 一个反直觉的判断

**工具型 agent 的真正对手不是 Coze，是"用户懒得配置"。**

Coze 吃掉的是"懒得配置 + 通用需求"用户。
工具型 agent 服务的是"愿意花 3 小时配置一次 + 个性化需求"用户。

后者是少数派，但 LTV（终身价值）远高于前者。
——这正是 2-8 法则：20% 的深度用户贡献 80% 的价值。

**所以终局判断**：**不是被吃掉，是分层共存**。
- Coze 类平台 = 浅层广度（80% 用户）
- 工具型 agent = 深度个性（20% 用户）
- 两者不竞争，甚至可以合作（蒸馏、桥接）
