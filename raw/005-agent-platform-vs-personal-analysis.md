# 平台型 agent 与工具型 agent ——分层共存，不是谁吃掉谁

> 横纵分析法深度研究报告
> 研究时间：2026-06-03 | 所属领域：AI 产品策略 / Agent 生态 | 研究对象类型：概念框架

---

## 一、一句话定义

「平台型 agent 与工具型 agent 分层共存」是一个关于 AI agent 产品市场分化方向的判断框架。核心主张：以 Coze 为首的平台型 agent 产品将走向「广度覆盖——服务 80% 用户的通用需求」，而以 OpenClaw / Hermes / Reasonix 为代表的工具型 terminal agent 将守住「深度个性化——服务 20% 用户的高价值工作流」。两者不在同一层竞争，甚至可以双向合作（MCP 桥接 + 技能蒸馏）。

---

## 二、纵向分析：AI agent 的三年分化路

### 2.1 萌芽期（2023——概念引爆）

2023 年是 AI agent 概念从学术界走向公众的引爆点。

这一年，AutoGPT 在 GitHub 上获得 160k+ star，让「AI 自主完成任务」从一个研究概念变成了开发者手里可以跑的东西。紧随其后的 BabyAGI、AgentGPT 把同一个 idea 用不同方式实现了一遍。与此同时，LangChain 和 LlamaIndex 作为 agent 编排框架迅速崛起——它们不是 agent 本身，而是搭 agent 的「脚手架」。

这个阶段的特征非常清晰：**技术门槛极高**。你要会写 Python、懂 LLM API、理解 chain/agent 的概念、能调试 prompt。用户画像几乎是清一色的 AI 工程师和研究者。OpenAI 在这个时期发布了 GPTs Store——算是第一次有人尝试把 agent 创建门槛降到「自然语言」级别，但 GPTs 更像是「封装好的对话机器人」，离真正的 agent（自主规划、工具调用、多步执行）还有距离。

关键矛盾：**agent 能力有了，但使用它的人太少**。因为脚手架太沉。

### 2.2 框架混战期（2024——人人都想搭平台）

2024 年是 agent 框架的爆发年。

一边是开源社区：Claude Code（Anthropic 的 terminal agent）、OpenClaw（18789 star，跨平台 API 编排）、Hermes Gateway（轻量消息路由）、Reasonix（cache-first 编程代理）——这些工具的特点是：**跑在你的终端里，直接操作你的文件系统、浏览器和 API**。

另一边是大厂入场：字节跳动推出 Coze（扣子），定位「零代码 AI 智能体开发平台」；百度跟进智能体平台；阿里推出百炼；腾讯推出元器。它们的特点是：**云端运行、拖拽式编排、零代码、生态闭环**。

这一年能看出两条路线的分化：

- **工具型 agent**（OpenClaw / Hermes / Reasonix）：把 AI 嵌入到开发者已有的工作流里。你是写代码的，agent 是你的协作者。你决定它做什么、怎么做。
- **平台型 agent**（Coze / 百度 / 阿里）：把 AI 封装成独立的「技能包」。你是用户，你告诉它你要什么结果，它来执行。

两条路线的核心差异不在于技术（底层都是 LLM + 工具调用），而在于**产品观念**——工具型 agent 把自己定位为「人的延伸」，平台型 agent 把自己定位为「人的替代」。

2024 年底出现了一个标志性事件：OpenAI GPTs Store 上线不到半年就陷入长尾困境——热门 GPT 集中在「写文案」「做图」「翻译」几个品类，真正深入行业场景的 GPT 少之又少。问题不在技术，在「行业 know-how 不在 GPTs 里，在用户的 prompt 里」。

### 2.3 分化期（2025——两条路各自碰壁）

2025 年是两条路都碰壁的一年。

**平台侧**：Coze 在国内积累了大量用户，但用户活跃深度不够。大量用户「试用一个 skill → 觉得不够好 → 离开」。核心问题：平台可以让你快速搭一个 agent，但搭出来的 agent 没有「个人记忆」——它不认识你的业务、你的文件、你的习惯。每次对话都是陌生人。

**工具侧**：OpenClaw / Hermes / Reasonix 在 AI builder 圈层获得认可，但出不了圈。核心问题：你需要懂命令行、懂配置文件、懂 Git。对于一个只想「让 AI 帮我审合同」的法务来说，学 Hermes 的成本远高于打开 Coze。

两条路同时碰壁不是巧合。它暴露了一个结构性矛盾：**AI agent 的能力进步很快，但产品化一直没跟上**。平台有广度没深度，工具有深度没广度。

### 2.4 收敛期（2026——各就各位）

2026 年是分化路径开始收敛的一年。

Coze 3.0 是一个关键节点。它的 Skill Store 不再只是一个「GPTs 列表」，而是变成了**行业 know-how 的封装层**。法务类案生成、公众号爆款写作、金融市场分析——这些 skill 不只是 prompt 模板，它们内置了检索策略、分析框架、输出模板。**Know-how 在 skill 里，不在用户的 prompt 里。**

这解决了平台侧的核心矛盾：用户不需要自己摸索怎么搭 agent，skill 已经替他把 80% 的工作做好了。

同期，工具侧也在进化。OpenClaw 发展了跨平台 API 编排能力，Hermes 强化了消息路由，Reasonix 主打了 cache-first 的性价比优势。更重要的是，MCP（Model Context Protocol）在 2025 年底到 2026 年逐渐成熟，为平台与工具之间的协作提供了一个标准化接口。

**2026 年的格局开始清晰**：平台做行业 skill 集市，工具做个人 workflow 深度。两者从「竞争」走向「分层」。

### 2.5 阶段划分总结

| 阶段 | 时间 | 核心特征 | 核心矛盾 |
|------|------|---------|---------|
| 萌芽期 | 2023 | AutoGPT 引爆概念，技术门槛极高 | agent 有能⼒但没用户 |
| 框架混战期 | 2024 | 工具型 vs 平台型两条路分化 | 工具太沉，平台太浅 |
| 分化期 | 2025 | 两条路各⾃碰壁 | 有广度没深度，有深度没广度 |
| 收敛期 | 2026 | 各就各位，分层雏形出现 | 平台和工具开始找到各自生态位 |

## 三、横向分析：竞争图谱

### 3.1 场景判断

本文研究的不是单一产品，而是一个概念框架下的两类产品形态。竞品分析不再是「A vs B」，而是**两种产品哲学的对位**。这属于场景 B（少量竞品：平台型 vs 工具型），但每类内部选取最有代表性的成员逐一分析。

### 3.2 平台型 agent：代表玩家

**Coze 3.0（字节跳动）**

- **定位**：零代码 AI 智能体开发平台 + Skill Store 行业技能市场
- **核心能力**：拖拽式工作流编排、MCP 协议支持、多模型接入（豆包 + 第三方）
- **目标用户**：非技术用户（运营、市场、法务、产品经理）
- **优势**：字节生态加持（豆包 + 飞书 + 抖音），零门槛上手，skill 持续增长
- **劣势**：数据隐私（所有数据经过云端）、个人化深度有限、被字节生态锁定
- **用户口碑**：上手快但深度不够；适合"试试看"，不适合"天天用"

**百度智能体平台**

- **定位**：基于文心大模型的智能体创建平台
- **优势**：搜索流量入口，百度生态（百家号、百科、文库）
- **劣势**：模型能力相比 Coze 接入的第三方模型偏弱，开发者生态弱于字节
- **用户口碑**：流量优势明显，但产品质量和技术更新速度不如 Coze

**阿里百炼**

- **定位**：企业级 AI agent 开发平台，强调与阿里云生态集成
- **优势**：企业级客户基础，电商场景（淘宝/天猫）天然适配
- **劣势**：面向企业而非个人创作者，配置复杂度高
- **用户口碑**：适合中大型企业，个人创作者嫌重

**OpenAI GPTs Store（全球对标）**

- **定位**：ChatGPT 内置技能市场
- **优势**：全球最大 LLM 用户基础，ChatGPT 品牌认知度
- **劣势**：GPTs 局限于对话场景，缺乏工作流编排能力；行业 know-how 在用户的 prompt 里不在 GPTs 里
- **用户口碑**：方便但不深入，用户尝试一次后留存率低

### 3.3 工具型 agent：代表玩家

**OpenClaw**

- **定位**：跨平台 API 编排 agent，跑在用户终端
- **核心能力**：文件系统操作、浏览器控制、代码执行、多 API 编排
- **目标用户**：AI builder、开发者、内容创作者
- **优势**：直接操作本地资源，隐私可控，不依赖平台
- **劣势**：需要技术背景（命令行 + Git + Markdown），无图形界面
- **用户口碑**：高价值用户的深度工具，但学习曲线陡

**Hermes Gateway**

- **定位**：轻量级消息路由 agent，桥接多 message platform
- **核心能力**：Slack/Discord/微信消息接入，agent 路由分发
- **目标用户**：需要跨平台 agent 通信的开发者
- **优势**：轻量，专注消息层，可与其他 agent 组合使用
- **劣势**：功能单一，依赖外部 agent 做具体执行
- **用户口碑**：在小圈子里口碑好，但知名度低

**Reasonix（cache-first terminal agent）**

- **定位**：面向编程和内容创作的 cache-first terminal agent
- **核心能力**：长会话 token 成本优化，DeepSeek 原生集成，文件系统交互
- **目标用户**：内容创作者 + 开发者，注重 token 成本和上下文持续性的用户
- **优势**：token 成本低（cache-first），隐私可控，离线可用
- **劣势**：命令行界面，出圈困难，需要用户主动配置
- **用户口碑**：少量但极高的用户忠诚度——用上了就回不去

**Claude Code（Anthropic）**

- **定位**：官方 terminal agent，与 Claude 深度集成
- **核心能力**：代码读写、文件操作、命令行执行
- **目标用户**：软件开发者
- **优势**：Anthropic 官方出品，与 Claude 模型深度整合，体验流畅
- **劣势**：仅限编程场景，不面向内容创作
- **用户口碑**：开发者圈层高度认可，被认为是 terminal agent 的标杆

### 3.4 生态位分析

当前格局是**两强分立，中间真空**：

```
                深度（个性化工作流）
                      ↑
                      │
        工具型 agent  │     ★ 中间地带
        (OpenClaw/    │     （空白）
         Hermes/      │
         Reasonix)    │
                      │
                      │
   ←──────────────────┼──────────────────→ 广度（通用场景）
                      │
                      │
        平台型 agent  │
        (Coze/百度/   │
         阿里)        │
                      │
                      ↓
                浅度（开箱即用）
```

**中间地带的空白**是目前最大的市场机会：
- 没有产品能同时做到「零门槛上手」和「深度个性化」
- Coze 可以让你 5 分钟搭一个 agent，但它不认识你的业务
- OpenClaw 可以深度适配你的 workflow，但你需要花 3 小时配置
- 这个空白在 1-2 年内不会被填上——不是技术做不到，是产品观念做不到

### 3.5 趋势判断

**平台侧的趋势**：Coze 3.0 的 Skill Store 方向是对的——把 know-how 封装进 skill。但平台天然不适合做深度个性化，因为个性化 = 非标准化 = 没有规模效应。字节不会让 Coze 去适配每个用户的独特工作流，那不符合平台经济学。

**工具侧的趋势**：OpenClaw / Hermes / Reasonix 这类工具的用户增长会慢，但 LTV 远高于平台用户。它们的问题是「用户获取」——如何让非技术用户愿意跨过命令行门槛。MCP 协议可能是一个突破口：如果平台 skill 可以通过 MCP 被本地 agent 调用，工具型 agent 就同时获得了「广度（平台的 skill 库）+ 深度（本地 workflow）」。

**最大变量**：字节/OpenAI 如果决定做「个人 agent」产品（把 Coze/ChatGPT 的能力从云端下沉到本地），工具型 agent 的生存空间会被大幅压缩。但目前没有任何迹象表明大厂愿意做这件事——个人 agent 是苦活累活，规模效应差，与平台的商业模式冲突。

## 四、横纵交汇洞察

### 4.1 历史如何塑造了当下的竞争位置

把时间线拉长看，平台和工具的分化不是设计出来的，是**被同一个矛盾逼出来的**。

2023-2024 年，所有人都想解决同一个问题——「怎么让更多人用上 AI agent」。平台侧的回答是「降低门槛到零」，工具侧的回答是「嵌入已有工作流」。

这两个回答现在看来各有道理，但放在当时，它们是对同一个压力的不同反应：**agent 能力强了，但没人会用**。

Coze 选择了降低门槛，但这意味着它必须牺牲深度——因为深度的代价是复杂性，而复杂性对抗零门槛。
OpenClaw/Hermes 选择了嵌入工作流，但这意味着它必须接受狭窄的用户面——因为深度个性化天然只服务少数人。

**今天的格局，是 2024 年的选择锁定的。**

### 4.2 平台和工具各自的优势和劣势，根在哪儿

**平台的优势根在「规模」**：Coze 可以投入 100 个人去维护一个法务 skill，因为这 100 个人的成本能摊到 100 万用户头上。工具型 agent 做不到。

**工具的劣势根也在「规模」**：一个 Reasonix skill 可以深度适配一个人的写作风格，但不可能适配 100 万人。没有规模效应，就没有资源去做精致化。

**平台的优势根在「分发」**：用户打开 Coze 就能看到 100 个 skill，不用搜不用装。工具型 agent 的 skill 需要用户自己去 GitHub 找、clone、配置。

**工具的劣势根也在「分发」**：正因为找 skill 的门槛高，用户一旦找了、配了、用了，就形成了切换成本。Coze 上换个 skill 不用 1 分钟，OpenClaw 换个 skill 要重读 README、改配置、测试——**麻烦本身就是护城河**。

### 4.3 一个反直觉的判断：麻烦是工具型 agent 的护城河

这是整个分析里最反直觉的一个点。

对平台来说，用户的低切换成本是卖点——「随时换，没有负担」。
对工具型 agent 来说，用户的切换成本高反而是好事——你让用户花 3 小时配置了一个 Hermes workflow，他下个月还在用。

**麻烦 = 深度 = 留存。**

这不是说工具型 agent 应该故意做难用。而是说，愿意花时间配置工具的用户，本身就是高价值用户。他们的 LTV 是平台用户的 10-100 倍。这不是 2-8 法则，这是 2-98 法则——2% 的深度用户贡献 98% 的生态价值（开源的贡献者、内容的创作者、工具的传播者）。

### 4.4 三个剧本

**剧本一（最可能）：分层共存 → 中间地带逐渐被填满**

Coze 继续做广度，OpenClaw/Hermes 继续做深度。MCP 协议成为连接两端的标准接口：Coze 出行业 know-how，本地 agent 出执行能力。中间地带慢慢被「带 skill store 的本地 agent」填上。对用户来说，最好的体验是「Coze 帮我审合同，本地 agent 把合同存到我的文件夹、更新我的任务表、给我的合伙人发一条微信」。

**剧本二（最危险）：平台下沉到个人 agent 层**

字节决定把 Coze 的能力从云端下沉到本地，做一款「个人 agent 桌面版」。这意味着字节愿意牺牲规模效应去抢深度用户市场。可能性不高，但如果发生了，工具型 agent 的生存空间会被挤压到非常狭窄的 niche——只有对数据隐私极度敏感的用户（医疗、法律、金融）才会选择纯本地方案。

**剧本三（最乐观）：工具型 agent 通过 MCP 吃到平台的 skill 红利**

MCP 协议成熟后，工具型 agent 成为平台的「消费端」——不跟平台竞争行业 know-how，而是借助平台的 skill 生态来增强自己的执行能力。Coze 的法务 skill 通过 MCP 暴露给 OpenClaw，OpenClaw 拿到法务判断后执行本地操作（写文件、发消息、推 PR）。这是真正的「分层合作」。

### 4.5 回到一个更根本的问题

Coze 3.0 和 OpenClaw/Hermes/Reasonix 的关系不是「谁替代谁」，而是**同一个趋势的两个侧面**。

这个趋势是：**AI agent 正在从「技术能力展示」变成「产品化服务」**。

Coze 代表的是产品化的「广度路径」——让更多人用上。
工具型 agent 代表的是产品化的「深度路径」——让用上的人用得更好。

两条路都必要，两条路都成立。
它们不是在争同一个市场，而是在定义同一个市场的上下限。
