# #005 收敛篇：三条内容线可用素材调研

> 调研目的：三条内容线（repo运营 / API不平等 / 三阶段）
> 都指向同一个问题——「你的 AI 工作流长在平台还是长在自己身上」。
> 本文归纳每条线有哪些真实事例可以用作文章的「收敛段」。

---

## 一、repo 运营 → "为什么工作流长在自己身上"

### 素材 1：PR #14/#15 — "公开系统本身"的洞察

**仓库位置**：`inbox/2026-05.md`（5/24 条目）

合入 PR #14/#15 后意识到，真正的价值不是发内容，而是把「怎么发内容」这个系统公开。Coze 可以帮你写内容，但不会告诉你这个选题为什么值得写——因为选题判断来自于 6 个月的 repo 对话历史，这些历史沉淀在 git 里，不在 Coze 的数据中心里。

**收敛角度**："平台 agent 帮你走捷径，但走多了就没有认知基线。你的决策历史长在 git 里还是长在平台的数据库里？这个问题的答案决定了你的护城河。"

### 素材 2：express lane 的边界设计

**仓库位置**：GOVERNANCE.md §3.5

typo / 链接修复 / 发布记录可以豁免 PR，但 raw/ 和政策文档不行。这是有意识的设计——对抗「AI agent 帮你改一切」的诱惑。

**收敛角度**："Coze 帮你改一切看起来很美好，但有些东西不能改——你在平台上分不清'优化'和'篡改'。工具型 agent 允许你自己画这条边界。"

### 素材 3：humanizer 兜底方案

**仓库位置**：`raw/2026-05-25-add-humanizer-into-workflow.md`

当 humanizer skill 不可用时，有 vendored prompt fallback。系统不依赖任何一个外部服务的可用性。

**收敛角度**："平台服务随时可能不可用，但你的 repo 不会。当你依赖 6 个外部服务来跑一个工作流时，你就是平台的租客。"

## 二、API 不平等 → "平台不给就自己长"

### 素材 1：22 分钟 12306 查票 API

**仓库位置**：`posts/x.md` post-2026-05-25-001

browse.sh 已有 322 个站点适配器，12306 是其中一个。0 token 完成，不是爬 HTML 是直接调站点的数据接口。等效于官方 API 但不依赖平台开放。

**收敛角度**："12306 永远不会给你开 API，但你的 agent 可以自己长出来。这是个人工具在平台面前的谈判筹码——你有 bypass 能力。Coze 能做到吗？不能。Coze 的所有 skill 都跑在字节的服务器上，字节不会让它去调隔壁竞品的数据。"

### 素材 2：微信群里的亚马逊卖家

**仓库位置**：`inbox/2026-05.md`（5/26 条目）

listing 生成跑稳了，卡在推上去那一步——没有 API。方案发到群里后 3 人说要去研究，1 人要 PR 链接。

**收敛角度**："Coze 能帮你写亚马逊 listing，但推不到亚马逊上。平台 agent 在最后一公里天然断腿——你服务的平台不会给你的竞争对手开 API。"

### 素材 3：药企品牌控价

**仓库位置**：`posts/moments.md` post-2026-05-28-001

一家药企问每个经销商要 API 来监控价格。结构性问题：合作式监控筛掉的是"不想被监控的人"（即最需要被监控的渠道）。

**收敛角度**："有些商业世界值得被监控的角落，平台 agent 根本看不见。Coze 的数据范围被字节的服务器边界锁死——这是工具型 agent 的 20% 用户的刚需场景。"

## 三、三阶段 → "第二阶段造什么车"

### 素材 1：项目的三阶段映射

**仓库位置**：`inbox/2026-05.md`（5/27 条目）

bb-browser 适配器（让 agent 长出 API）、访谈方法论（AI 穷举 + 人判断）、social content loop（agent 从生成推到发布）——全部落在第二阶段。

**收敛角度**："我问自己一个问题：我在造平台车还是个人车？Coze 在造平台车（把工具链做成服务），我在造个人车（把工具链存在自己 repo 里）。两辆车都能跑，但终点不同——平台车卖给 80% 的用户，个人车服务 20% 的深度场景。"

### 素材 2：同一周三个独立信源指向同一方向

**仓库位置**：`posts/x.md` post-2026-06-02-001

@yibie 的 X 帖（训练小模型是 2026 年最被低估的 AI 技能）、MiniMax M2 技术报告（229B 参数只激活 4.3%）、《当机器开始花钱》的三阶段叙事——同一个星期指向"少买 GPU，多做事情"。

**收敛角度**："三个独立信源同一周指向同一个判断：第二阶段窗口已经开了。现在的问题不是'用不用 AI'，而是'你的 AI 工作流长在平台还是长在自己身上'。"

### 素材 3：蚂蚁 3 亿笔 agent 支付的公式

**仓库位置**：`posts/x.md` post-2026-05-28-003

支付价值公式从 V≈N_user×F_frequency（人类注意力受限）→ 亿级 agent × 毫秒级连续触发。

**收敛角度**："Phase 3 的场景是 agent 自己花钱。你的 agent 的钱包放在哪？平台帮你管还是你自己管？这个问题的答案决定了你现在 architecture choices。"

## 四、三条线收敛段参考写法

> 以下是一个示例段落，展示如何把三条线的例子串成一个完整的叙事段落，非最终定稿。

```
三条线最终指向同一个问题。

repo 运营讲的是「你的 workflow 凭什么长在自己身上」——

PR #15 合入那天我发现，真正的壁垒不是内容质量，
是系统迭代的决策历史。
Coze 可以帮你写，但它不知道你为什么这么写。
这是我的 repo，不是平台的数据库。

API 不平等讲的是「平台不给你 API，agent 自己长」——

12306 22 分钟长出查票 API，
药企控价筛掉了不想被监控的人。
平台 agent 的最后一公里天然断腿，
你的竞争对手不愿意让你调数据。
工具型 agent 的存在，
是因为有些墙角平台不愿意也钻不进去。

三阶段讲的是「第二阶段你在造什么车」——

我把所有项目做了一次映射，
全部落在 Agent 工具链这条线上。
Coze 也在造车，
但它造的是巴士，我造的是公路车。
巴士能装很多人但只跑主干道，
公路车上不了高速但能去山脚。

三个问题，一个答案：
你的 AI 工作流长在平台还是长在自己身上？
```
