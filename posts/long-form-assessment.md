---

### 升级理由

1. **话题本身具有示范性**：把真实 PR（#14、#15）、真实 GOVERNANCE.md、真实 express lane 拿出来讲，是可验证的方法论，不是空泛建议。

3. **自我繁殖属性**：这篇长文本身就是这套系统的产物，发出去后收到的每条反馈都可以成为下一次 PR。
4. **X 上无同类**：竞品搜索未见以中文写作、面向海外华人受众、公开记录整套系统的同类内容。

## 候选：《API 不平等：当中国互联网不给 AI 开门》

**评估日期**：2026-05-26
**来源**：inbox/2026-05.md#2026-05-26-16-30 + 微信群聊「AI 出海工具链」
**状态**：建议升级 ✅

---

### 竞品调研摘要

| 方向 | 代表内容 | 与本方案的差异 |
|------|----------|----------------|
| AI 写电商文案 | 大量公众号/小红书教程 | 只解决「生成」，不解决「推送」— 文案写好了还是手动粘贴 |
| 亚马逊 SP-API 教程 | 官方文档、开发者博客 | 仅限亚马逊，申请门槛高，中国平台无对应物 |
| RPA/浏览器自动化 | UiPath、影刀、Selenium 教程 | 图形界面操作，脆弱、慢、token 消耗大，反爬升级即失效 |
| browse.sh 原站 | https://browse.sh | 400+ 站点 API 端点集合，但绑定云端浏览器，无法本地 agent 调用 |

**结论**：跨境电商圈内容集中在「AI 生成文案」和「官方 API 教程」两条线，没有人讲「不申请 API，让 agent 通过浏览器自己长出 API」。蓝海。

---

### 升级理由

1. **受众完全不重叠**：现有内容面向 AI builder，这篇面向跨境电商实操者（亚马逊卖家、TikTok 店主、1688 选品人）。这是第二条增长线，不消耗现有选题资源。
2. **有 external social proof**：群聊中已有亚马逊卖家把 listing 生成跑稳两个品类，就差接 API 推上去。他看见方案的反应是「我去研究起来」。不是假设需求，是 already-in-motion。
3. **概念有穿透力**：「API 不平等」四字比「repo 运营」更直觉。大模型越强越刺眼——agent 能力强了但没入口。能出圈。
4. **产品化路径清晰**：repo 运营是个人方法论，模仿成本高。API 不平等 → bb-browser 适配器 → 读者 clone 后她的 agent 立刻能调京东 API。不是「看我怎么做」，是「你也能做」。
5. **竞品真空**：跨境电商+AI agent+中国平台 API 这个交叉点，目前没有人用中文系统性地写。

---

### 候选标题（3 个）

1. **《API 不平等：中国平台不对 AI 开放接口，然后呢？》**（概念驱动，适合出圈）
2. **《我让 AI 自己「长」出了京东和小红书的 API》**（技术好奇感，吸引 AI builder）
3. **《跨境电商的 AI 最后一公里：没有 API 怎么把内容推上去？》**（直击痛点，吸引跨境电商从业者）

---

### 建议文章结构

```
一、引子：一段群聊 —「阿里的 API 不可能随便开放」
二、API 不平等的真相：硅谷开放 vs 中国封闭
三、两个死胡同：等官方 API（等不到）vs 浏览器自动化（反爬）
四、第三条路：0 token CDP 提取 — browse.sh 翻译 → bb-browser 适配器
五、现场演示：12306 查票 / 京东搜索 / 小红书热门（均 0 token）
六、电商全链路愿景：AI 写文案 → AI 推 listing → AI 改价
七、开放问题：这东西能走多远？平台会封吗？
```

---

### 升级理由

1. **框架有穿透力**：三阶段叙事（修路→造车→收过路费）比纯技术文章更直觉，非技术受众也能理解产业位置。

4. **时机对**：2026 年正是第二阶段窗口期，文章有"现在该做什么"的行动号召力。

---

## 候选：《不是被吃掉，是分层共存：平台型 agent 与工具型 agent 的终局》

**评估日期**：2026-06-03
**来源**：inbox/2026-06.md#2026-06-02（Coze 3.0 直播观感）+ inbox 后续三条延伸调研
**状态**：建议升级 ✅

---

### 竞品调研摘要

| 方向 | 代表内容 | 与本方案的差异 |
|------|----------|----------------|
| Coze 官方/科技媒体 | Coze 3.0 发布会、产品报道、skill store 概览 | 纯产品介绍，无行业定位、无工具型 agent 视角的对位分析 |
| 平台经济分析 | a16z、Benedict Evans 的 AI 平台化文章 | 西方视角，以 OpenAI/Anthropic 为中心，不讨论中文平台生态（字节/百度/阿里） |
| Agent 框架讨论 | LangChain / AutoGPT 社区的技术争论 | 集中在技术栈选择（框架 vs 裸调 API），无产品观念层面的平台 vs 个人分析 |
| 大厂 vs 创业公司叙事 | 即刻/知乎上的碎片讨论 | 散点讨论「大厂做 AI agent 会赢吗」，无系统性框架对立两方 |

**结论**：中文内容生态中有大量「Coze 评测」和「大厂 vs 创业队」的碎片争论，但没有人用"平台广度 vs 个人深度"的分层共存框架来系统分析。这个角度有稀缺性。

---

### 升级理由

1. **框架有解释力**：「分层共存」（平台=广度→80%用户，工具=深度→20%高LTV用户）比「颠覆/革命」叙事更贴合真实市场竞争结构。有 2-8 法则的理论支撑。
2. **inbox 素材充足**：三条延伸调研（skill 反哺、协作模式、产品观念映射）提供了产品、架构、战略三个层次的素材，不是空谈框架。
3. **三条线汇聚**：之前三条内容线（repo 运营→内容创作者、API 不平等→跨境电商、三阶段→AI 从业者）都指向同一个下半场问题——「你的 AI 工作流长在平台还是长在自己身上」。这篇可以是三条线的"收敛篇"。
4. **长期话题**：「个人 vs 平台」不是一篇能说完的，发出去会不断被验证/打脸，有持续追踪价值。

---

### 候选标题（3 个）

1. **《不是被吃掉，是分层共存：平台型 agent 与工具型 agent 的终局》**（判断型，面向 AI builder 和从业者）
2. **《Coze 3.0 来了，个人 agent 还有戏吗？》**（话题驱动，出圈力强）
3. **《你的 AI 工作流长在平台还是长在自己身上？》**（问题型，引发读者自我定位讨论）

---

### 建议文章结构

```
一、引子：Coze 3.0 直播看到一半，我松了口气
二、Coze 在卖什么（不是技术参数）
    - 低技术门槛 × 好泛化 × 真实工作场景
    - 模型能力是基础设施，不是卖点
    - Skill store 的本质：行业 know-how 集市
三、平台经济的必然性
    - 平台做广度（千万用户，千万场景）
    - 三大风险：全栈下沉、know-how 网络效应、算力成本
四、但个人 agent 有 5 个不可替代性
    - 隐私合规 / 延迟离线 / 个性化深度 / 跨平台资产 / 创作主权
五、分层共存模型
    - 平台 = 80% 用户的浅层广度
    - 工具型 agent = 20% 用户的深度个性
    - 不竞争，可合作（MCP 桥接 + 技能蒸馏）
六、三条内容线的收敛
    - repo 运营（内容创作者）→「你的工作流凭什么长在自己身上」
    - API 不平等（跨境电商）→「平台不给你 API，agent 自己长」
    - 三阶段（AI 从业者）→「第二阶段造车，你造的平台车还是个人车」
七、对读者的判断：你是 80% 还是 20%
```
