## post-2026-05-24-001：我用 GitHub 管理内容创作，三月复盘

状态：draft
来源：inbox/2026-05.md#2026-05-24-22-24
首发平台：小红书
audience：想入门 AI 工作流的产品经理 / 设计师 / 运营
是否升级长文：可联动（见 posts/long-form-assessment.md）

### 笔记草稿

**标题（候选）**
- 我把自媒体当代码库来运营，用了三个月
- 一个工程师的内容系统：GitHub + AI agents + PR 审批
- 用 GitHub 管理创作，比 Notion 好用在哪里

---

**正文**

作为一个在美国工作的工程师，我用一套「反常识」的方式运营内容：

**把自媒体当 GitHub repo 来管理。** 字面意思，不是比喻。

---

**我的系统长这样：**

📁 inbox/：随时记录碎片想法（手机备忘录 → 粘贴进来）
📁 drafts/：长文草稿，按编号版本管理
📁 posts/：按平台（X、小红书、朋友圈）拆分的短内容
📁 topics/：选题卡，从想法到发布全程追踪
📋 GOVERNANCE.md：锁死规则，对我自己和 AI 都生效

---

**核心逻辑：**

每一次改动都是一个 PR（Pull Request）。

AI 是常驻的 collaborator，帮我执行，但不能自己决策。

所有版本历史都在 git log 里，随时可以回溯。

---

**为什么不用 Notion / Obsidian？**

- Notion 没有真正的版本控制
- Obsidian 适合个人知识库，不适合「内容 + AI 协作 + 发布」的完整流程
- GitHub 天然支持 PR review、branch 隔离、commit message 追踪

工程师习惯用 code review 保证代码质量，同样的逻辑也适用于内容。

---

**闭环是：**

想法 → inbox → PR → 发布 → 反馈 → 下一个想法

AI 帮我完成每一步的执行，我只负责判断和想法。

---

这个系统已经运行了三个月。

如果你也在找一种「能跟 AI 协作的内容系统」，这套方法可能值得参考。

有问题欢迎评论区聊 👇

---

**标签**
#AI创作 #内容创作 #个人系统 #GitHub #工具分享 #海外华人 #独立创作者 #AI工具

## post-2026-05-25-001：0 token 获得 12306 查票 API

状态：draft
来源：inbox/2026-05.md#2026-05-24-22-36
首发平台：小红书
audience：想入门 AI 工作流的产品经理 / 设计师 / 运营
是否升级长文：待观察

### 一句话观点

不重复造轮子是工程实践。

### 笔记草稿

**标题（候选）**
- 22 分钟，0 token，拿到 12306 查票 API
- 不重复造轮子，是我今年学到的最有价值的工程思维
- 我用现成的库，0 token 解锁了 12306 实时余票

---

**正文**

做技术的朋友应该都遇到过这种情况：

要做一个功能（比如查 12306 的列车时刻），本能反应是「去逆向它的 API」。

然后开始抓包、分析请求参数、处理加密、处理 session…半天就过去了。

---

**我最近换了一个思路：不重复造轮子。**

发现 browse.sh（一个 Browserbase 的产品）已经有 322 个网站的自动化方案，其中有一个就是 12306.cn/find-trains。

它不是开源的，但它的 skill 描述已经很清楚地告诉我：
- 这个 API 怎么调
- 需要什么参数
- 返回什么格式
- 有什么备选方案

---

**我是怎么做的：**

① 从 322 个 skill 里找到 12306 的
② 研究描述：先试 API，不行走浏览器
③ 在浏览器上下文中调用 12306 的查询接口
④ 返回 15 趟列车实时时刻 + 余票

---

**关键结果：**

| 车次 | 路线 | 用时 | 余票 |
|------|------|------|------|
| G25 | 北京南→上海虹桥 | 04:18 | 商务座4张 |
| G27 | 北京南→上海虹桥 | 04:32 | 商务座14张·一二等座有 |
| G29 | 北京南→上海 | 04:43 | 商务座10张 |

22 分钟完成，0 token 消耗。

---

**这个思路的通用性：**

browse.sh 的 322 个 skill 里，有 142 个是 browser/hybrid 方法的，都可以用同样的方式翻译成我的本地适配器。

我已经翻译了 11 个，验证了 4 个（12306、小红书、Airbnb、eBay）。

---

**核心结论：**

最有价值的技能变成了：知道哪里有轮子，怎么装到自己的车上。

这套模式正在开源，有兴趣的可以关注后续。

## post-2026-05-26-001：一个月 AI 花了 ¥33，我的省钱方法

状态：draft
来源：inbox/2026-05.md#2026-05-25-17-08
首发平台：小红书
audience：想省钱的 AI 重度用户 / PM / 运营（半技术画像，§6 允许，§3.3 打折）
是否升级长文：否（先发 X thread 测试兴趣）

### 一句话观点

AI 月费 ¥33 vs ¥200 的差距，不是"找便宜方案"的结果，是"不再为方便溢价买单"的副产品。

### 近似实现 / 待查

见 posts/x.md post-2026-05-26-001。

### 笔记草稿

**标题（候选）**
- AI 月费 ¥33 vs ¥200，差在哪
- 一个月用了 4,155 次 AI，花了 ¥33
- 重度用 AI 的人，别再付订阅了

---

**正文**

我每天重度用 AI——写文案、改代码、查资料、处理数据。基本离不开了。

上个月一共调了 4,155 次，410M tokens，花了 ¥33.36。

身边很多朋友也在用，ChatGPT Plus、Claude Pro，月费 ¥145-200。用量不到我的十分之一，花的钱是我的好几倍。

不是炫账单。想说一件大部分人没意识到的事：你为 AI 付的钱，大部分在为"方便"买单——不是为"用量"买单。

---

**账单拆开看**

重活（写代码、复杂分析）：1,029 次，86.6M tokens，¥33
轻活（改文案、翻译、查东西）：3,126 次，324M tokens，几乎免费

轻活量是重活的 4 倍。花的是零头。

这个比例本身就说明问题：便宜到一定程度之后，你的使用习惯会变。

---

**三组方案对比**

同样 4,155 次、410M tokens 的用量，不同方案月费：

ChatGPT Plus 订阅：≈ ¥145。不够——有次数和频率限制，这个用量会被降速
OpenAI API 按量：≈ ¥8,300。够用，但贵
DeepSeek API 按量：¥33。够用。便宜到你不考虑"优化 prompt"这件事了

差距 250 倍。海外模型价格来自 OpenRouter 实时定价（2026.05），DeepSeek 来自我的实际账单。

---

**便宜的真正效果**

最明显的变化不是"省钱了"。

而是你不再精打细算了：
- 完整文件、超长上下文，直接丢进去
- 失败了重试，不心疼
- 不会再想"这个 prompt 怎么精简到 200 tokens"

¥33 一个月，买的不是 token——是"不用优化"的自由。

---

**我的教训**

一开始我也被"API"这两个字劝退了。觉得要写代码。

后来发现很多工具已经把 API 集成好了：桌面客户端（Chatbox、Cherry Studio 等）、浏览器插件、聊天 App。你只需要注册一个账号、填一个 key——体验和用 ChatGPT 网页版一样。

花了两个月才意识到这件事，多付了几个月订阅费。

---

**适合谁，不适合谁**

适合：每天频繁用 AI、月费超 ¥100、愿意花 10 分钟设置一次的人
不适合：偶尔用的人。订阅的方便程度值那几十块，不值得折腾

我自己每个月翻一次账单。不是为了省 ¥33——是为了提醒自己，工具选型的账值得定期重算。
