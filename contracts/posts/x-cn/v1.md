## 1. 平台特性（决定下面所有规则的根因）
### 1.1 平台定位（写给 agent 看的）

X 中文圈层的内容生态特征：
- 算法以"互动率"为核心，转发 > 评论 > 引用 > 点赞
- 时间线竞争极激烈，前 1 行决定是否被读完
- 容忍尖锐观点，奖励"有判断的人"，惩罚"无主张的搬运工"
- 长推文（thread）只有当首条够强时才值得展开
- 中文 X 用户偏好"短、准、有刺"，反感小红书化的笔记腔

**因此本平台的内容必须做到：一句话能立住，刺出来才发，没刺就别发。​**

## 1.2 平台特定写作规则

### 必须满足
1. **首句即钩子**：第 1 行必须独立成立，能让人在 0.5 秒内决定继续看
2. **观点优先于信息**：信息搬运请放小红书，X 上必须有"我怎么看"
3. **单条单核**：一条推文只承载一个观点，不要在 280 字里塞 3 个论点
4. **结尾留刺或留口子**：要么收得干脆，要么开放讨论，不要软收尾
5. **Thread 只用于结构性论证**：单条说不完才开 thread，不要为了凑长度而 thread

### 明确禁止
1. **小红书化笔记腔**：emoji 分点、"姐妹们"、"先收藏"、"宝子"
2. **公众号腔**：长铺垫、起承转合、"今天我们来聊聊"
3. **空 hashtag 堆砌**：超过 2 个 hashtag、与正文无关的 trending tag
4. **强行 thread**：1/8、2/8 但每条都没干货
5. **AI 翻译腔**：明显的英文句法直译（"这是因为..."、"值得注意的是..."）

## 2. 平台评分维度（满分 60，加上通用 40 = 100）

### 2.1 第一推钩子（0-15）

X 平台第一推决定一切。单独打分。

| 分数 | 判据 |
|---|---|
| 13-15 | 看到第一推就想点开 thread / 想转发 / 想评论 |
| 10-12 | 第一推有钩子但不够锋利 |
| 7-9 | 第一推合格但平庸，不会吸引点击 |
| 4-6 | 第一推像新闻摘要，没有人格 |
| 0-3 | 第一推就是"下面我要讲" |

**钩子模板**（不强制，但可参考）：
- 反共识断言："大家都说 X，其实 Y"
- 具体数字 + 反差："我用 3 个月发现 80% 的 ABC 是错的"
- 第一人称证据："我把自媒体当 GitHub repo 运营 6 个月，结论是..."
- 强提问："如果 agent 写得比你好，你还写吗"

**Anti-pattern（v1.1 追加）：任一触发，钩子分上限 8**

- **软抽象开场**："一个不寻常的 X" / "聊聊 X" / "想说一下 X" / "一件值得说的事"
- **元描述开场**："这是一篇关于 X 的 thread" / "下面 N 推讲 Y" / "今天写一下 X"
- **无锚反问**："为什么 X？" 但前置没有具体场景或证据
- **价值预告**："说一下这条支线为什么值得公开" / "今天分享一个有意思的发现"

理由：钩子的作用是 0.5 秒内让人停下来，软抽象开场把这个功能让给了"读者凭好奇心继续看"——大多数读者不会继续。

### 2.2 thread 节奏（0-15）

如果是 thread，看推与推之间的张力；如果是单推，看句子之间的张力。

| 分数 | 判据 |
|---|---|
| 13-15 | 每一推都让人想看下一推，节奏紧凑 |
| 10-12 | 主体节奏好，个别推可删 |
| 7-9 | 节奏平稳但缺爆点 |
| 4-6 | 中段冗长，读者会划走 |
| 0-3 | 完全没有节奏感，像论文摘要 |

### 2.3 中文表达力（0-15）

中文 X 圈层对"中文写得好不好"非常敏感。

| 分数 | 判据 |
|---|---|
| 13-15 | 句子有节奏，用词准确，长短句交替自然 |
| 10-12 | 表达干净，但缺少风格 |
| 7-9 | 表达通顺但偏译文腔 |
| 4-6 | 句子拖沓，定语长串，明显机翻感 |
| 0-3 | 中文不像中文，全是"基于...对...进行..." |

**中文 X 特别警惕的译文腔模式：​**

老式 GPT 译文腔：
- "在...的背景下" / "针对...而言"
- "进行 + 动词"（"进行优化"→"优化"）
- "性"字滥用（"差异性""同质性"）
- 长定语前置（"一个能够帮助创作者实现内容自动化生产的系统"）

**新式英文修辞腔（v1.1 追加，现代 GPT 输出常见，每条触发 -3）：**
- **短句自问自答**："PR #14 和 #15 刚合并。这两个 PR 的内容是什么？在 repo 里有完整记录。"——典型英文 setup-question-answer 句式直译
- **setup-punch 句式**："Z 看起来 A。其实是 B。"连续 ≥2 次（GPT 最爱的"反差感"句式）
- **短句叠加排比**："Z 的 Y。不是 A。是 B。"（断句过密，掩盖空话）
- **元描述+断言**："不是口号，是真实系统。"（用"不是 X 是 Y"假装在反驳一个没人说过的论点）

### 2.4 可转发性（0-15）

X 的核心传播单位是"被转发"。

| 分数 | 判据 |
|---|---|
| 13-15 | 我自己看到都想转——观点鲜明、有截图证据、能代表读者表态 |
| 10-12 | 有转发理由但不够强 |
| 7-9 | 信息有用但不会被转，会被点赞收藏 |
| 4-6 | 只适合自己看 |
| 0-3 | 看完没有任何分享冲动 |

**扣分项（v1.1 追加，挖坑不给糖反 pattern）：**

| 情形 | 扣分 | 备注 |
|---|---|---|
| **承诺但不给**：出现 "详见 / 在 repo 里有完整记录 / 后续会讲 / 答案在 X" 但未给链接/截图/引用 | **-5** | 一律严格——X 用户不会回头找，挖坑不给糖即等于伪信息密度 |
| **不可访问引用**：出现 ≥2 个 "PR #N" / "issue #N" / "commit hash" 但读者无法访问该 repo | -3 | 未给 URL 或 repo 非公开 |
| **元承诺空头**："留着以后写" / "下次展开" / "等我有时间" 占用结尾段 | -3 | |

**态度（v1.1 review feedback 明确）**：默认一律严格 -5，**X 用户的行为模式是 timeline 单次扫过**，不存在"以后回头看"的可能。

**唯一豁免**：明确标注 "Part 1/N" 的系列 thread，第一篇允许预告，但必须给：
- 后续发布时间（"下周一 GMT+8 9pm 发 Part 2"）或
- 后续发布锚点（"会发在 @account 主页"）

豁免条件不满足，按 -5 处理；满足，扣分降为 -1。

理由：可转发性的本质是"读者愿意把它分享给别人"——挖坑不给糖让转发者承担"那个糖在哪"的解释成本，转化为不转发。

## 3. 字数与格式

- 单推 ≤ 140 中文字符（含标点）
- thread 单推同上，建议 5-12 推之间
- 不用 # 话题标签（X 中文圈不靠话题，靠转发）
- 不用 emoji 做分隔符；正文 emoji 全文不超过 2 个
- 不用 markdown（X 不渲染）

## 4. 扣分项前后对比

### 例 1：AI 词汇 + vague attribution

**​❌ 扣分版（AI 痕迹: 3, 第一推钩子: 5）​**
> 在 AI 工具快速迭代的当下，越来越多创作者开始尝试用 agent 赋能内容生产。研究显示，这种新型工作流能显著提升效率，值得每一位创作者深入思考。

问题：赋能、研究显示、值得思考——3 个 red flag 全中。第一推没有任何具体证据。

**​✅ 改写版（AI 痕迹: 9, 第一推钩子: 13）​**
> 我把自媒体当 GitHub repo 运营了 3 个月。
> 
> 6 个 PR、2 条 express lane 规则、inbox/posts/topics 三层升级机制。
>
> 结论：内容生产可以是工程问题，但前提是先承认"好稿子"从来没被定义过。

### 例 2：thread 节奏失控

**​❌ 扣分版（thread 节奏: 4）​**
> 1/ 接下来我要讲讲我的内容工作流
> 2/ 首先，我会把想法记在 inbox
> 3/ 然后，我会从 inbox 升级到 posts
> 4/ 最后，发布出去

问题：每一推都是"接下来"，没有独立价值，读者第 2 推就划走。

**​✅ 改写版（thread 节奏: 12）​**
> 1/ inbox 是我系统里压力最低的地方——只能追加，不能删除
> 2/ posts 是 inbox 的"晋级版"——必须按平台拆，不允许一稿多投
> 3/ topics 是 posts 的"沉淀版"——只放跑过 3 篇以上的方向
> 4/ 这套结构最反直觉的一点：inbox 越乱越好，posts 越严越好

### 例 3：译文腔

**​❌ 扣分版（中文表达力: 5）​**
> 这是一个能够帮助创作者基于 GitHub 仓库实现内容自动化生产的系统性解决方案。

**​✅ 改写版（中文表达力: 13）​**
> 一句话：把内容生产塞进 GitHub repo，让每条想法都有 PR 编号。

## 5. 晋级阈值（覆盖通用层）

中文 X 比其他平台更卷，阈值上调：

- **rejected**：触发任一硬性禁区，或第一推钩子 < 7
- **needs_revision**：总分 < 75
- **reviewing**：75 ≤ 总分 < 88
- **approved**：总分 ≥ 88 且第一推钩子 ≥ 11

## 6. 平台特定硬禁区（在 v1-common 之外追加）

任一触发，直接 rejected：

1. **挂人 / 影射具体个人未脱敏**
2. **直接复制墙内平台原文搬运到 X**
3. **以"听说 / 据说"开头但无来源**

## 7. 合格 X Post 最小骨架

agent 在写 X post 时，应该对照以下骨架自检：

```
[钩子句：单独成立，0.5 秒内立住]

[展开 1-3 句：给出立场 + 1 个具体证据 / 例子]

[收尾：留刺、留口子、或反问；不软收]
```

或 thread 版：

```
1. [钩子推：本身就是好推]
2. [证据 / 反例]
3. [推论 / 命名]
4. [收尾：判断或留口]
```

## 8. 通过门槛（覆盖 v1-common §7）

X 平台对 AI 痕迹和原生度更敏感，因此覆盖通用阈值：

- `total >= 85` 且 `平台原生度 >= 12` 且 `AI 痕迹 >= 8`：approved
- `70 <= total < 85` 或 `平台原生度 < 12`：needs_revision
- `total < 70` 或 `观点锐度 <= 4`：回退重写

**特别规则**：观点锐度 ≤ 4 的草稿一律不能在 X 发布，建议改投 Moments 或丢弃。

## 9. Express lane（来自你 inbox 反思）

允许 AI agent 直接追加 inbox 反馈，但发布前必须人工确认。
agent 可以提议 draft，但不允许跨过 reviewing 直接 approved。
