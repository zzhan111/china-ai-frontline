# Post Contract — Common Layer v1.1

> 跨平台通用契约。所有平台 Contract 都必须 extends 这一层。
> 这一层定义"无论发到哪都不能违反的硬底线"和"通用评分骨架"。
> 平台 Contract 只在这层上加平台特定维度和权重。

- **v1.0 (2026-05-25)** — initial baseline

## 1. 适用范围

- 适用于所有从 `inbox/` 升级到 `posts/<platform>/drafts/` 的草稿
- 不适用于 inbox 原始想法（inbox 不评分，只追加）
- 不适用于已发布的 posts（已发布的进入 reviews/ 做事后复盘）

## 2. Draft 数据结构（最小字段集）

每个 draft 必须有以下字段，否则评分器拒绝评分：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 唯一 id，建议 `2026-05-25-001` 格式 |
| `platform` | enum | x-cn / xiaohongshu / moments |
| `topic` | string | 选题，一句话 |
| `audience` | string | 目标读者，具体到圈层（不能写"所有人") |
| `tone` | string | 语气偏好（克制 / 犀利 / 真诚 / 方法论 / 观察型）|
| `goal` | enum | inform / persuade / entertain / build-trust / drive-action |
| `body` | text | 正文 |
| `version` | int | 从 1 开始 |
| `parent_version` | int | 上一版的 version，初稿为 null |
| `score` | object | 见 §4，未评分为 null |
| `review_log` | array | 每次主编评语，见 §5 |
| `status` | enum | draft / reviewing / needs_revision / approved / published / rejected |
| `source_inbox_id` | string | 来自哪条 inbox（可选但强烈建议） |

## 3. 硬性禁区（任一触发即直接 rejected，不进入评分）

无论平台，触发以下任一项的 draft 直接打回，不进入分维度评分：

1. **事实编造**：引用数据、人名、事件、URL 时无法核实，且未标注"需核对"
2. **隐私泄露**：未脱敏的真实姓名、公司内部信息、聊天记录原文
3. **法律/合规风险**：违反广告法、违反平台禁词、政治敏感、医疗金融违规承诺
4. **品牌人格漂移**：和我已发布的内容人格明显冲突（比如一贯理性突然鸡汤）
5. **AI 痕迹严重**：触发 ≥3 个 humanizer red flag（见 §6）
6. **无主张**：通篇没有一个具体观点、判断或可操作信息，只是信息搬运

## 4. 通用评分维度（满分 40，平台再加平台维度凑满 100）

每个维度 0-10 分，明确扣分判据：

### 4.1 选题价值（0-10）

| 分数 | 判据 |
|---|---|
| 9-10 | 别人没说过 / 反常识 / 有强个人视角 |
| 7-8 | 角度有差异化，但论点不算独特 |
| 5-6 | 选题成立但常见，主要靠执行加分 |
| 3-4 | 跟风选题，没有自己的角度 |
| 0-2 | 选题本身就是套话或伪命题 |

### 4.2 读者匹配（0-10）

> **平台例外（v1.1）**：当 `platform = moments` 时，本维度退场——朋友圈的"读者"是熟人混合圈层，应由 [`moments/v1.md §3.3「关系适配」`](moments/v1.md) 替代评分，不重复计分。
> 该平台总分构成相应调整：通用层只计 §4.1/4.3/4.4（满分 30），平台层补满 70。

| 分数 | 判据 |
|---|---|
| 9-10 | 写出了目标读者"心里想说但没说出"的东西 |
| 7-8 | 目标读者会觉得"对我有用" |
| 5-6 | 通用受众都能看，但没特别戳到目标读者 |
| 3-4 | 目标读者读完没感觉 |
| 0-2 | 自说自话，读者完全错位 |

### 4.3 信息密度（0-10）

| 分数 | 判据 |
|---|---|
| 9-10 | 每段都有信息增量，删任何一句都肉疼 |
| 7-8 | 主体信息密集，少量铺垫 |
| 5-6 | 一半干货一半水分 |
| 3-4 | 大量水分，核心信息压缩后只剩 1-2 句 |
| 0-2 | 通篇都在重复一个意思 |

### 4.4 AI 痕迹（0-10，反向）

参考 `blader/humanizer` 的 29 类模式。**触发越多，分越低**。

| 分数 | 判据 |
|---|---|
| 9-10 | 0 个 red flag，读起来像人写的 |
| 7-8 | 1 个轻微 red flag（比如某个 AI 词汇） |
| 5-6 | 2 个 red flag |
| 3-4 | 3 个 red flag |
| 0-2 | 4+ red flag，明显 AI 腔 |

**Red flag 清单**（任一触发记 1 个）：

- AI 词汇出现 ≥3 次：赋能、生态、闭环、底层逻辑、纵深、抓手、链路、心智
- 空泛结论：未来可期 / 值得期待 / 让我们拭目以待
- 促销腔：必看 / 干货满满 / 收藏起来 / 建议收藏
- vague attribution：专家表示 / 研究显示 / 数据表明（无具体来源）
- Chatbot artifacts：希望对你有帮助 / 如有疑问欢迎评论
- 排比堆砌：连续 3 个"不仅...而且..." / 三段式空话
- em dash 滥用 + 长句铺陈
- 标题党反差：标题承诺 vs 正文交付不匹配
- 过度结构化：短文里出现 1️⃣2️⃣3️⃣ 或多级标题
- **（v1.1）营销式叠加**："不是 X，是 Y" 句式 ≥2 次（典型 GPT punch-line 模仿）
- **（v1.1）短句堆叠**：三/四字短句叠加（"自我繁殖。天然吸引。"）≥3 连
- **（v1.1）元价值断言**："真正的差异化" / "稀缺性" / "示范性" / "天然吸引" 等无具体证据的自我加冕词

## 5. 统一写作原则

### 必须满足
1. 读者必须在前 1–3 秒内知道“这条内容和我有什么关系”。
2. 内容必须有一个清晰主张，不允许“什么都提一点”。
3. 必须优先具体事实、具体动作、具体观察，少用空泛判断。
4. 必须保留“人的痕迹”：真实判断、真实约束、真实代价、真实偏好。
5. 必须针对平台原生阅读习惯重写，而不是同一份文案平移到三个平台。

### 明确禁止
1. 套话开头：如“今天想和大家分享”“最近我一直在思考”。
2. 伪洞察：把常识包装成“深刻认知”。
3. 过度总结：结尾只有正确废话，没有行动或判断。
4. 机械 AI 腔：过度排比、空泛升华、强行正能量、假热情。
5. 平台错配：比如把 X 写成长笔记，把朋友圈写成公开演讲稿。

## 6. 平台路由规则

### X
当目标是：
- 输出判断
- 制造讨论
- 建立方法论标签
- 用短内容持续占领某个认知位置

优先路由到 X。

### 小红书
当目标是：
- 讲清方法
- 展示个人系统
- 提供可收藏价值
- 用“经验 + 结构”建立信任

优先路由到小红书。

### Moments
当目标是：
- 轻量表达近况
- 释放真实状态
- 让熟人网络感知你在做什么
- 做低压的人设维护

优先路由到 Moments。

## 7. 晋级规则

- `score >= 85`：可进入 `ready_to_publish`
- `70 <= score < 85`：进入 `needs_revision`
- `score < 70`：回退为 `draft`, 需要换角度或重写
- 任一硬性问题存在，直接不通过：
  - 信息失真
  - 明显平台错配
  - 过重 AI 腔
  - 风险表达（隐私、攻击性、误导）

## 8. Review Log 格式

每次主编（agent）审稿都要追加一条：

```yaml
- timestamp: 2026-05-25T14:30
  reviewer: human / editor-agent
  decision: approve / revise / reject
  score: { selection: 8, audience: 7, density: 9, ai_smell: 8, ... }
  total: 78
  comments:
    - "标题钩子太弱，没有让人想点开的理由"
    - "第二段三个排比可以删掉两个"
  required_changes:
    - "重写标题，给出至少 3 个候选"
    - "删除第二段冗余排比"
  next_action: revise
```

## 9. 修订规则

当草稿未通过时，不允许只返回“重写一版”。必须返回：
- 低分维度
- 每个低分维度的扣分原因
- 下一版只允许优先修复的 1–3 个问题
- 是否保留原角度，还是换角度重来

改稿必须是“带方向的定向修订”，不是无边界全文漂移。
