# Post Contract — 小红书 v1

> extends: contracts/posts/v1-common.md
> 平台：小红书
> 本合同只定义小红书平台特定维度，硬性禁区、Draft 字段、Review Log 格式均继承 v1-common。

## 1. 平台定位（写给 agent 看的）

小红书内容生态特征：
- 算法以"完读 + 收藏 + 评论"为核心，收藏权重极高
- 用户以"找答案 / 找方法 / 找参考"为主要消费动机
- 容忍长内容（800-1500 字），但要求强结构和强可读性
- 封面 + 标题决定点击，正文决定收藏
- 反感纯观点输出，奖励"有方法论 + 可执行 + 可复用"的内容

**因此本平台的内容必须做到：让读者觉得"这条值得收藏"，否则就是失败。​**

## 2. 平台特定写作规则

### 必须满足
1. **标题必须包含具体收益**：读者看到标题要能答出"我能学到什么"
2. **正文必须有结构**：分点、小标题、序号都可以，但不能一坨流水账
3. **必须有可执行成分**：方法、步骤、清单、对照表，至少出现一项
4. **必须有"我"的痕迹**：真实使用 / 真实踩坑 / 真实判断，不能像维基百科
5. **结尾给出收藏理由**：不是"求收藏"，而是让收藏变成自然动作

### 明确禁止
1. **X 化短推**：100 字以内、纯观点、无方法
2. **公众号长铺垫**：开头讲故事讲 200 字才进主题
3. **空泛干货**：列了 10 条但每条都是常识
4. **硬广腔**：直白推产品、限时优惠、"冲冲冲"
5. **过度 emoji**：每行都带 emoji、emoji 比文字多

## 3. 平台特定评分维度（60 分）

### 3.1 标题与封面承诺（0-15）

小红书是"封面驱动型"平台，标题在评分中权重高。

| 分数 | 判据 |
|---|---|
| 13-15 | 标题给出具体收益 + 具体场景 + 差异化角度 |
| 10-12 | 标题清晰，但角度常见 |
| 7-9 | 标题中规中矩，没有点击理由 |
| 4-6 | 标题模糊，看不出是写给谁的 |
| 0-3 | 标题党 / 无关 / 完全没钩子 |

**扣分点**：
- 标题超过 20 字：-3
- 全是形容词没有名词收益：-3（"超绝 / 神仙 / 绝绝子"）
- 承诺与正文不符：-7

**增分点**：
- 出现具体数字（"3 个 / 5 步 / 7 天"）：+2
- 出现具体身份（"程序员 / 新手妈妈 / 跨境运营"）：+2
- 出现具体场景（"通勤 / 周末 / 出差"）：+2

### 3.2 结构清晰度（0-15）

| 分数 | 判据 |
|---|---|
| 13-15 | 清晰的小标题 / 序号 / 段落，扫读 3 秒能抓主线 |
| 10-12 | 结构存在但稍乱，需要读 2 段才理清 |
| 7-9 | 结构弱，靠读者自己组织 |
| 4-6 | 一坨流水账，没有视觉锚点 |
| 0-3 | 完全无结构，像聊天记录 |

**扣分点**：
- 全文超过 3 段没有任何分隔：-5
- 列表项之间长度严重不均（一个 2 字一个 50 字）：-3
- 用 markdown 多级标题（小红书不渲染）：-3

**注意**：小红书不渲染 markdown，agent 必须使用 emoji / 数字 / 符号做视觉分隔，但不允许滥用。

### 3.3 可执行价值（0-15）

| 分数 | 判据 |
|---|---|
| 13-15 | 读完立刻能用：清单、步骤、模板、对照可直接复制 |
| 10-12 | 有方法但需要读者自己整理 |
| 7-9 | 有方向无方法，需要继续找 |
| 4-6 | 全是观点和感受，没有"怎么做" |
| 0-3 | 纯抒情或纯信息陈列，无任何执行成分 |

**扣分点**：
- 通篇"建议大家 / 应该 / 需要"但不说怎么做：-5
- 给方法但缺关键参数（"用某 app" 但不说哪个）：-3
- 步骤之间逻辑断裂：-5

**增分点**：
- 给出可直接抄走的清单 / 模板 / 对照表：+5
- 标注每步的预期时间 / 成本 / 难度：+3
- 提供失败案例 + 修正方案：+5

### 3.4 真实痕迹（0-15）

小红书最反感"AI 总结百科腔"，奖励"我亲自踩过坑"。

| 分数 | 判据 |
|---|---|
| 13-15 | 有具体时间、地点、人物、数字、踩坑细节 |
| 10-12 | 有个人视角但细节弱 |
| 7-9 | 中性陈述，看不出谁写的 |
| 4-6 | 像爬虫聚合 / 维基风格 |
| 0-3 | 完全 AI 总结腔，零个人痕迹 |

**红线**（任一触发 ≤4 分）：
- 通篇用"我们 / 大家"而不是"我"
- 没有任何具体数字 / 时间 / 场景
- 列举优点缺点像产品说明书

**增分点**：
- 主动暴露自己的失败 / 代价 / 改变想法的过程：+5
- 给出"我之前以为 X，后来发现 Y"的认知更新：+3

## 4. 长度规则

- **下限**：500 字（低于则收藏价值不足）
- **甜区**：800-1300 字
- **上限**：1800 字（超过需要拆系列）

低于 500 字直接 needs_revision；超过 1800 字必须拆。

## 5. 增分项（可叠加，最多 +10 不封顶）

- 提供可截图保存的对照表 / 清单：+5
- 给出反常识结论并解释为什么：+3
- 主动比较 2-3 个方案优劣：+3
- 引用一手数据 / 自己的实测：+5
- 标注适用人群 / 不适用人群：+3

## 6. 平台特定硬禁区（在 v1-common 之外追加）

任一触发，直接 rejected：

1. **违反小红书广告法**：极限词（最 / 第一 / 唯一）、绝对承诺、医疗效果承诺
2. **导流外站**：明显引导加微信 / 加群 / 跳转外链
3. **抄袭其他笔记**：未注明来源的二创
4. **图文不符**：正文承诺 vs 配图无关（agent 在生成时若依赖配图则必须显式说明）

## 7. 合格小红书笔记最小骨架

[标题：身份 / 场景 / 数字 / 收益 任选 2-3 项组合，≤20 字]
[开头 2-3 句：身份代入 + 痛点描述 + 本文承诺]
[主体：分点呈现，每点 = 小标题 + 1-2 句解释 + 1 个具体例子或数字]
[失败 / 踩坑段落：1 段，主动暴露代价]
[收尾：明确适用人群 + 自然给出收藏理由（如"我自己也常翻回来看"）]


## 8. 通过门槛（覆盖 v1-common §7）

小红书对结构和可执行价值更敏感，因此覆盖通用阈值：

- `total >= 85` 且 `可执行价值 >= 11` 且 `真实痕迹 >= 11`：approved
- `70 <= total < 85` 或 `可执行价值 < 11`：needs_revision
- `total < 70` 或 `结构清晰度 <= 5`：回退重写

**特别规则**：可执行价值 ≤ 6 的草稿不能在小红书发布，建议改投 X（作为短观点）或丢弃。
