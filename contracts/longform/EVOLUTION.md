## 2026-05-29 — v0 building blocks 诞生（来源：004 v1 人工评审）

公众号长文是 `contracts/posts/`（短社媒）覆盖不到的体裁。004 访谈初稿 v1 第一次跑“AI 铺满型长文”，用户人工评审给出关键诊断：

- **架构层（优点，保留）​**：从“人的故事 → 初心想法 → 实践 → 下一个想法”形成闭环；结尾把人设丰富起来，读者能清晰感受到。
- **文笔层（病灶）​**：① 流水账、一笔带过、没有重点；② 缺“活人感”；③ 不与读者共情（陌生概念不解释，如“反应釜”；不会用“内在对话逻辑”带读者探索）；④ 场景调性偏“直播间/自媒体喧嚣”，cheap/虚假，应改为稳重/人文/引发思考。

由此抽象出 6 条长文特有维度 **LF-1～LF-6**（见 `building-blocks.md`）。正面样本锚定为南方人物周刊《失控的爱》（`raw/references/`）。

### 关键判断

- **contract first 哲学延续**：先沉淀 building block，不急着写评分器。长文主观维度（活人感/节拍）机械检测难，先靠 SKILL/人评，等样本够再编译 v1。
- **不重复造轮子**：AI 痕迹 / 硬性禁区 / 观察者红线全部继承 `posts/v1-common` + 001 宪法，longform 只加 6 条特有维度。

### Open items（v1 编译前）

- [x] 004 v2 重写后，把“哪些 LF 维度真的改善了文笔”回填本文件（v1→v2 的 before/after 是 LF 维度的第一组实证）。
- [x] 等下一篇长文（005?）再走一遍，凑齐每条维度 ≥2 病例/正例。
- [x] humanizer 当前文档限定 `posts/*.md`、明确不含 `drafts/`（见 `skills/humanizer-usage.md` §处理范围）。本次用户要求对长文 draft 跑 humanizer——属工作流扩展，需决定：是否把 humanizer 处理范围正式扩到 `drafts/` 长文，还是长文用独立的 craft-pass。先记录，v1 时定。

### How to append

## 2026-06-09 — 第二类长文接入：意见/判断型（来源：005 evolution + README）

005 是 building blocks 的第二个实战样本，且**不是** 004 那种人物特稿，而是“从产品观察到趋势判断”的意见型长文（Coze 3.0 等平台型 Agent 观察 → “平台型 vs 本地 Agent 分层共存”判断）。它暴露了 v0 的一个隐藏假设：**LF-1～LF-6 全部用“人物”措辞写成，默认长文 = 人物特稿。​** 005 证明同一批维度对意见型同样成立，但表现形态不同：

- 活人感（LF-1）：靠**场景**而非人物——“三个人的早晨”用工作镜头验证抽象分工。
- 概念锚定（LF-3）：靠**技术翻译**——MCP/CLI/workflow → 后台连接/调流程；“个人 Agent” → “本地 Agent”。
- 反流水账（LF-4）：靠**不堆产品功能**——Coze 3.0 降为观察入口，立刻升一层到趋势。

由此对 `building-blocks.md` 做两件事（v0 → v0.2）：

1. **类型化**：引入“长文两种子类型”——A 人物特稿（004）/ B 意见型（005）。LF-1～LF-6 每条改为按类型落地（`A:` / `B:`），保留 004 全部样本，补 005 的 B 类样本。
2. **加 3 条 B 专属维度**：LF-7 观察→公共判断、LF-8 传播锚点（一句能被带走的话）、LF-9 立场公允/反稻草人。来源是 005 README 的四条方法 + 选题卡“不贬低 Coze”红线。

> 取舍记录：005 README 方法三“复杂技术 → 生活负担”**未单列**为 LF，而是并入 LF-3·B（概念锚定的意见型落地），避免与“概念锚定”重叠——同一个母判据“概念首现处要为读者落地”。方法四“场景即验证”并入 LF-1·B，非新维度。

### 关键判断

- v0 → v0.2 让 building blocks 从“人物特稿专用”升级成**​“长文通用骨架 + 类型模块”​**。这也改变了 v1 编译形态预判：`contracts/longform/v1.md` 很可能是“共用脊柱（LF-1～6 通用判据）+ 类型评分模块（A/B 各自落地判据与阈值）”，而非单一评分表。
- 继承不变：AI 痕迹 / 硬性禁区 / 观察者红线仍全部继承 `posts/v1-common` + 001 宪法，longform 只加类型化的 LF。

## 2026-06-10 — 第三类长文接入：热点调研型（来源：006 evolution）

006 是 building blocks 的第三个实战样本，也不是 004 的人物特稿、005 的意见型长文，而是**热点调研型长文**：围绕 Fable 5 / Mythos 5 发布 24 小时内的事件窗口，完成事实验证、benchmark 对照、社区反馈归纳、成本拆解、机制风险和产业判断。

它暴露了 v0.2 的第二个隐藏假设：**B 意见型虽然能覆盖“判断”，但还不能覆盖“热点调研”的时效、事实层级和材料密度问题。​** 006 证明热点长文不是新闻搬运，也不是普通观点文，而是“事实密度 + 时效窗口 + 公共判断”的组合：

- 事实验证（新增 LF-10）：先区分官方事实、社区反馈、作者判断和待验证信息，再进入观点。
- 三层拆解（新增 LF-11）：不只问“强不强”，还要拆“账本 / 机制 / 体验”——价格、usage credits、静默降级、长任务成本，最后落到用户处境。
- 版本策略（新增 LF-12）：热点调研型追求“信息窗口期内达到发布标准即发布”，不必复用 002 那种 Preview → 定向修订流程。

由此对 `building-blocks.md` 做三件事（v0.2 → v0.3）：

1. **类型扩展**：引入第三类长文——C 热点调研型（006）。长文类型从 A/B 升级为 A 人物特稿 / B 意见型 / C 热点调研型。
2. **补 C 类落地判据**：LF-1～LF-6 增补 C 类样本；LF-7～LF-9 从 B 专属调整为 B/C 判断型共用维度。
3. **新增 C 专属维度**：LF-10 事实验证优先、LF-11 账本/机制/体验三层拆解、LF-12 时效窗口内达到发布标准即发布。

> 取舍记录：006 的“个人工作流痕迹不得进入正文”没有并入 LF-10，而是单列为 longform 通用红线。原因是它不只影响热点调研，也影响人物特稿和意见型长文：正文可以保留“24 小时调研”这种中性方法描述，但不得把 AI / agents / 工具链参与写作的过程当成正文内容。写作脚手架应留在 `evolution.md`，不能进入发布稿。

### 关键判断

- v0.2 → v0.3 让 building blocks 从“长文通用骨架 + A/B 类型模块”升级成**​“共用脊柱 + 判断型模块 + 热点调研模块”​**。v1 编译形态进一步明确：LF-1～LF-6 是共用脊柱，LF-7～LF-9 是判断型长文共用模块，LF-10～LF-12 是热点调研型模块。
- 006 的核心方法不是“堆资料”，而是**从热点事实升到用户账本、平台机制和产业分工**。这让它从“Fable 5 发布分析”变成“前沿模型商业化拐点分析”。
- 热点调研型的版本策略应区别于意见型：只要事实核验、主线、边界、成本、争议和公共判断闭环，并通过 Contract 自检，就应在窗口期发布；继续打磨的边际收益可能低于错过窗口的损失。
