> **状态：building block，不是正式 contract。** 这里只累积"长文级"的写作维度与红线，等积累 ≥2–3 篇长文实战后再编译成可评分的 `contracts/longform/v1.md`（仿 `contracts/posts/v1-common.md` 的评分骨架）。
>
> **为什么单列 longform：** `contracts/posts/`（X / 小红书 / 朋友圈）管的是**短社媒**——前 3 秒钩子、信息密度、平台原生。公众号长文（人物特稿 / 长判断）的成败维度不一样：它要的是**活人感、与读者的内在对话、叙事节拍、概念藏进经历、克制**。短社媒 contract 的"AI 痕迹清单"仍然适用（继承），但不足以评一篇人物特稿。
>
> **继承关系：** longform extends `contracts/posts/v1-common.md` 的 §3 硬性禁区 + §4.4 AI 痕迹清单 + 001 宪法（`raw/2026-05-12-cowork-001-article-constitution.md`）的"观察者姿态 / 不下结论 / 无归纳清单 / 无公众号自指"红线。下面只加**长文特有**的维度。

## 长文的两种子类型（先定类型，再套维度）

长文不是单一体裁。到 005 为止跑通两类，成败维度**同源但表现形态不同**：

| 子类型 | 代表 | 主体 | 成功长这样 | 失败长这样 |
|---|---|---|---|---|
| **A 人物特稿** | 004 | 一个人 | 人物立起来，读者"看见"他 | 履历罗列、流水账 |
| **B 意见/判断型** | 005 | 一个判断 | 判断清楚、能被读者带走 | 产品流水账、术语墙 |

**用法**：先判定本篇是 A 还是 B，再套 LF 维度。LF-1～LF-6 两类都要过，但判据按类型落地（下面每条标 `A:` / `B:`）；LF-7～LF-9 是 **B 专属**（A 选配）。

## 长文特有维度（每条：判据 +「A 人物特稿」样本 +「B 意见型」样本）

### LF-1　活人感（抽象是否"立起来"）
**判据**：抽象（人物 / 论点）必须落到**具体动作 + 细节**，读者能"看见"，而非属性 / 履历 / 论点罗列。
- `A` 人物靠**具体动作 + 真实对白 + 感官细节**呈现。
  - ❌ 004 v1·写外挂的少年：事件一笔带过，"他写完外挂喜欢免费往外发"——是概述，不是场景。
  - ✅ 范文：宿舍"脚臭和汗臭夹杂的味道"、床"一有动作就吱呀作响"、尿频只能用"一个粉色的盆"；对白口吻有别（家人 vs 被规训的女孩）。
- `B` 没有主角人物，但判断要落到**具体的人在具体场景里的动作**——用工作镜头验证抽象判断（场景即验证，不是举例凑数）。
  - ❌ 005 v1.0/v1.2：判断停在概念层（"个人 Agent 是记忆层 / 调度层"），读者无画面。
  - ✅ 005 preview §06「三个人的早晨」：陈翻草稿查旧文找选题、林在地铁上只改一处、周调出三个月前评审会 CTO 的两条反对理由——抽象分工被三个工作镜头坐实。
- **红线（通用）**：通篇只有"是什么"（属性 / 论点）而没有"在做什么 / 说什么"，判失败。

### LF-2　与读者的内在对话（共情逻辑）
**判据**：叙述贴着**当下推理**走，让读者**同步发现**，而不是被作者预先告知结论；在读者会卡壳处，用"设问→带读者探索"的内在节奏。
- `A` 贴**人物**的当下推理。
  - ❌ 004 v1：用户原话"什么时候该以一种'内在的'对话逻辑来共情读者，隐藏在文本中带着读者去探索"——v1 缺这个。
  - ✅ 范文："素伶心想，管这么严，说不定表弟真摊上了大事"——读者跟着她推理，一起被骗、一起醒悟。
- `B` 全文由**一个读者也会问的问题**驱动，答案分步推进，不一次性抛结论。
  - ✅ 005：核心问题"平台都把能力打包好了，一个人还需要'自己的' Agent 吗？"——先答"需要"，再层层推进（不是因为更强 → 平台该赢 → 但差那 20 分 → 配置要消失 → 两者协作）。
- **红线（通用）**：一上来就抛完整结论、把读者当听众而非同行者，判失败。

### LF-3　概念锚定（术语藏进经历 / 场景，不科普）
**判据**：陌生概念**首次出现处**必须让读者懂——优先靠**一个具体场景 / 类比**让概念被"撞见"，其次才是一句白话括注。绝不堆术语。
- `A` 术语藏进经历。
  - ❌ 004 v1·01 节：用户批"什么是'反应釜'"没解释；"面壁智能"无注释。
  - ✅ 范文：全程不科普"戒网瘾机构是什么"，靠验孕棒、迷彩服、叠豆腐块军被、洗澡要"特批"让读者自己懂。
- `B`（尤其科技意见文）除"藏进场景"外，还要把**技术词翻译成读者能感到的负担 / 收益**，而非科普协议本身。
  - ❌ 005 v1.2：MCP / CLI / workflow / 自托管 密集出现，准确但劝退。
  - ✅ 005 preview 的翻译表：

    | 技术表达 | 发布稿表达 |
    |---|---|
    | MCP / CLI | 后台连接、调用外部能力 |
    | workflow | 调流程 |
    | 自托管 / 本地部署 | 跑在你能控制的环境里 |
    | 记忆层 / 调度层 | 记得你、替你判断怎么做 |

    并把门槛问题翻成用户问题——"不想为了一个更好的 AI，先变成半个技术人员"。**选词本身就是锚定决策**：005 把"个人 Agent"改成"本地 Agent"，选更贴大众直觉、自带"资料 / 隐私 / 可控"暗示的词。
  - 原则：降**进入成本**，不降**判断深度**——逻辑保留，措辞变轻。
- **操作（通用）**：术语清单逐个检查首现处有无"读者侧落点"（004 含：反应釜、function call、端侧、LoRA、智能密度、面壁智能、世界模型、OPC）。

### LF-4　叙事节拍 / 反流水账（每段有重心）
**判据**：每节 / 每段有一个**重心**，有起伏、有取舍；不匀速平铺、不"看似写了很多却没重点"。
- `A` 每节一个**叙事鼓点**。
  - ❌ 004 v1：用户原话"很多地方像流水账一样一笔带过……没有重点"；典型病句"他离开内蒙古到天津的原因……便收住了"——一笔带过却让读者疑惑。
  - ✅ 范文：10 个编号小节，每节标题是一句戏剧性引语（"宝宝"/"我们家猫丢了都查监控啊"），每节一个 beat。
- `B` 判断要**分层推进**，产品信息**压成趋势入口**，不逐条罗列功能。
  - ❌ 005 v1.1：Coze 3.0 功能写满，读成产品评论。
  - ✅ 005 preview：只在开头点 Coze / WorkBuddy / Dumate，立刻升一层到"平台型 Agent 正在变成云端团队"。
- **红线（通用）**：A 出现"一笔带过却让读者更疑惑"的句子（给悬念不给信息，又非有意留白）/ B 退化成"它有哪些功能"的产品流水账——判失败 → 要么展开，要么删除，要么升一层。

### LF-5　藏与露（张力靠细节，不靠形容词）
**判据**：最大的信息放进最小的细节 / 最克制的判断；用白描和取舍制造张力，而非用"震撼 / 残忍 / 了不起"这类作者形容。
- `A` 把**信息**藏进细节。
  - ✅ 范文："这句话让虚空顿感不妙。他们两人从来不叫对方'宝宝'。"——两个字引爆悬念；母亲那封 **AI 生成的道歉信**，show 不 tell。
- `B` 藏掉**实现细节**，露出读者要记住的**判断**。
  - ✅ 005：藏掉 MCP / CLI / workflow / 自托管 / 多 Agent 技术细节；露出"平台会干活、本地 Agent 懂你、配置不该是用户的工作"。
- 继承 001 宪法（通用）：观察者姿态、不下结论、结尾定格在画面或一句不解释的话上。

### LF-6　场景调性（人文 / 稳重 > 喧嚣）
**判据**：长文要稳重、引发思考；**商业 / 自媒体 / 直播间 / 路演的喧嚣感要降为注脚**，不作为叙事底色。
- `A` 把采集现场的喧嚣降为脚注。
  - ❌ 004 v1：用户原话"直播间确实感到 cheap、虚假、不诚实……抓住深度、还原受访者、设定一个比较稳重、人文主义、引发人思考的场景"。v1 把"直播连麦"写进导语并反复出现。
  - **操作**：采集场景（直播间 / 路演 / 黑客松喧嚣）若非主题必需，降为一句脚注；正文锚定在人与思想。
- `B` 判断要落在**日常工作流**，不堆宏大技术叙事或行业口号。
  - ✅ 005：写文章前找素材 / 见客户前拼上下文 / 投资人追问时找决策依据——贴近读者真实工作，而非"AI 革命"宏大叙事。
- **注意（通用）**：这条与"真实质感 / 非 PR 通稿"红线不冲突——诚实交代信息来源仍要，但**不渲染**喧嚣场景、**不喊**口号。

## B 意见/判断型专属维度（A 选配；来源：005）

### LF-7　观察 → 公共判断（不要停在"它有什么功能"）
**判据**：意见型长文必须把**一个具体观察**（某产品 / 事件）升级成**可迁移的判断**。读者带走的不是"X 发布了什么"，而是"X 让什么分工 / 旧假设 / 趋势变清楚了"。
- ❌ 反例（005 v1.1）：Coze 3.0 写成全文主角 → 读者读成单一产品评论。
- ✅ 正例（005 preview）：Coze 3.0 / WorkBuddy / Dumate 降为开头观察入口，正文统一"平台型 Agent"，全文讨论"平台型 vs 本地 Agent 的新分工"。
- **红线**：通篇停在"它有哪些功能"、没有升一层到判断，判失败（与 LF-4·B 互为表里）。
- **操作**：定稿前自问三句——这个变化说明了什么？它让哪种旧分工失效？它让哪种新分工变清楚？

### LF-8　传播锚点 / 一句能被带走的话
**判据**：要有**一句金句**同时承担三个功能——概念解释 + 文章主线 + 传播记忆点；读者转发时能原样带走这一句。
- ✅ 正例（005）："平台型 Agent 的优势是：它会很多事。本地 Agent 的优势是：它知道你的事。"——一句锚定两个概念、给出全文判断、可被原样转发；结尾再压一层："平台负责能力。本地 Agent 负责上下文。真正的智能，发生在两者之间。"
- **注意**：金句 ≠ 营销式"不是 X 是 Y"空话（仍受 `v1-common §4.4` AI 痕迹清单约束）。金句必须**承载真实判断**，靠区分度而非修辞对仗成立。
- **操作**：定稿前找出"如果读者只记一句，是哪句"；若找不到，说明判断还没锚定。

### LF-9　立场公允 / 反稻草人（先扬后立）
**判据**：亮出己方判断前，先**诚实承认对立面的合理强项**（steelman），再谈己方不可替代。先扬后立比直接对立更可信。
- ❌ 反例（潜在）：把平台写成反派、把"本地 Agent"写成救世主 → 二元对立，读者不买账。
- ✅ 正例（005 §02）：单设一节"平台会吃掉大多数通用任务，这是好事"——"平台型 Agent 该赢……AI 终于从 demo 变成了基础设施"，先把对手抬到合理位置，§03 再给出"差的就是那 20 分"。
- **红线**：通篇只贬损对立面、不给对方任何合理性，判失败。
- 继承 005 选题卡"不贬低 Coze"红线。

## 与既有约束的关系（避免重复造轮子）
- **AI 痕迹**：直接用 `contracts/posts/v1-common.md §4.4` 的 red flag 清单（赋能/生态/闭环……、营销式"不是X是Y"、短句堆叠、元价值断言）。长文同样适用。
- **硬性禁区**：直接用 `v1-common §3`（事实编造、隐私泄露、合规、人格漂移）。
- **观察者/红线**：直接用 001 宪法五红线。
- 本文件**只加** LF-1～LF-9 这些长文特有维度，并按"A 人物特稿 / B 意见型"两种子类型落地；AI 痕迹、硬性禁区、观察者红线仍全部继承，不重复定义。

## 升级为正式 contract 的触发条件
- 已有 004（A 人物特稿）+ 005（B 意见型）两个样本，覆盖两种子类型。LF-1～LF-6 多数维度已有 A/B 两类样本；LF-7～LF-9 目前各只有 005 一个正例。
- 触发 v1 编译：当每条维度（按其适用类型）都至少有 **2 个独立病例/正例**时——B 专属维度需再凑一篇意见型长文。
- v1 形态预判：很可能是**"共用脊柱（LF-1～6 通用判据）+ 类型评分模块（A / B 各自的落地判据与晋级阈值）"**，而非单一评分表。编译时加 0–10 评分判据，并接入 `tools/`（若能机械检测）。
