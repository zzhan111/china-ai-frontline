## 长文的三种子类型（先定类型，再套维度）

| 子类型 | 代表 | 主体 | 成功长这样 | 失败长这样 |
| --- | --- | --- | --- | --- |
| **A 人物特稿** | 004 | 一个人 | 人物立起来，读者"看见"他 | 履历罗列、流水账 |
| **B 意见/判断型** | 005、007 | 一个判断 | 判断清楚、能被读者带走 | 产品流水账、术语墙 |
| **C 热点调研型** | 006、010 | 一个事件 / 争议 | 事实可靠、边界清楚、能从热点升到公共判断 | 跟风复述、资料堆砌、阴谋论化、过期新闻 |

**用法**：先判定本篇是 A、B 还是 C，再套 LF 维度。LF-1～LF-6 三类都要过，但判据按类型落地（每条标 `A:` / `B:` / `C:`）；LF-7～LF-9 是 **B / C 共用的判断型维度**（A 选配）；LF-10～LF-12 是 **C 专属**；LF-13 是 **B 专属**；LF-14 是 **C 专属**；LF-15 是 **B/C 共用**；LF-16 是 **通用 meta 维度**。

## 长文特有维度

### LF-1 活人感（抽象是否"立起来"）

**判据**：抽象（人物 / 论点 / 事件）必须落到**具体动作 + 细节**，读者能"看见"，而非属性 / 履历 / 论点 / 资料罗列。

- `A` 人物靠**具体动作 + 真实对白 + 感官细节**呈现。
  - 反例：004 v1·写外挂的少年：事件一笔带过，"他写完外挂喜欢免费往外发"——是概述，不是场景。
  - 正例：范文：宿舍"脚臭和汗臭夹杂的味道"、床"一有动作就吱呀作响"、尿频只能用"一个粉色的盆"。
- `B` 判断要落到**具体的人在具体场景里的动作**——用工作镜头验证抽象判断。
  - 反例：005 v1.0/v1.2：判断停在概念层，读者无画面。
  - 正例：005 preview §06"三个人的早晨"：陈翻草稿查旧文找选题、林在地铁上只改一处、周调出三个月前评审会 CTO 的两条反对理由。
- `C` 热点不是"新闻条目"，而是要落到**具体用户在具体任务里的体验 / 账单 / 反馈**。
  - 反例：只写"Fable 5 发布，benchmark 全面领先，社区热议"。
  - 正例（006）："200 美元 Claude Max 月费会员，跑 3 个任务就烧空""英文社区有人一个 session 三天烧了 4000 美元"。
  - 正例（010）："6 月 12 日，一个开发者在 V2EX 上发了一条帖子。'There's an issue with the selected model (claude-fable-5).'"——用一条真实的报错信息开场，把"出口管制"这个抽象政策变成读者能看见的终端截图。
- **红线（通用）**：通篇只有"是什么"而没有"在做什么 / 发生在谁身上"，判失败。

### LF-2 与读者的内在对话（共情逻辑）

**判据**：叙述贴着**当下推理**走，让读者**同步发现**，而不是被作者预先告知结论；在读者会卡壳处，用"设问→带读者探索"的内在节奏。

- `A` 贴**人物**的当下推理。正例：范文："素伶心想，管这么严，说不定表弟真摊上了大事"。
- `B` 全文由**一个读者也会问的问题**驱动。正例：005："平台都把能力打包好了，一个人还需要'自己的' Agent 吗？"；007："Agent 能不能作为独立的生产者干活？→ 能不能把劳动成果卖出去？"
- `C` 全文由**热点发生后读者真正会追问的几个问题**驱动：它是真的吗？它强在哪里？边界在哪里？为什么这么贵？这件事说明什么？。
  - 正例（006）："它确实很强 → 但封神有边界 → 真正的刺客不是标价 → 静默降级才是真正的不平等"。
  - 正例（010）："Fable 5 被封了怎么办？→ 中国开发者在行动 → GLM 5.2 在填空 → Kimi K2.7 面临同一个困境 → 监管在扩散 → 大众层吃瓜 vs 开发者层动手（温差）→ 不是替代，是填空"。每节回答一个递进的读者问题。
- **红线（通用）**：一上来就抛完整结论、把读者当听众而非同行者，判失败。

### LF-3 概念锚定（术语藏进经历 / 场景，不科普）

**判据**：陌生概念**首次出现处**必须让读者懂——优先靠**一个具体场景 / 类比 / 读者侧后果**让概念被"撞见"，其次才是一句白话括注。

- `A` 术语藏进经历。正例：范文全程不科普"戒网瘾机构是什么"，靠验孕棒、迷彩服、叠豆腐块军被让读者自己懂。
- `B` 把**技术词翻译成读者能感到的负担 / 收益**。正例：005 preview 翻译表（MCP/CLI → "后台连接、调用外部能力"）。
- `C` 用**技术事实解释用户处境和产业变化**，不做技术科普。
  - 正例（006）：静默降级翻成"你付的是 Fable 5 的价格，但某些任务实际拿到的是 Opus 4.8 的答案"。
  - 正例（010）：反蒸馏机制翻成"想防止被蒸馏就得多烧 token，多烧 token 用户体验就崩"——不到 20 个字，同时解释了机制和读者后果。
- **操作（通用）**：术语清单逐个检查首现处有无"读者侧落点"。

### LF-4 叙事节拍 / 反流水账（每段有重心）

**判据**：每节 / 每段有一个**重心**，有起伏、有取舍；不匀速平铺、不"看似写了很多却没重点"。

- `A` 每节一个**叙事鼓点**。正例：范文 10 个编号小节，每节标题是一句戏剧性引语。
- `B` 判断要**分层推进**，产品信息**压成趋势入口**。正例：005 preview 只在开头点 Coze / WorkBuddy / Dumate，立刻升一层到"平台型 Agent 正在变成云端团队"。
- `C` 热点调研要避免"资料夹式写法"。定稿前逐节标注"这一节解决哪个读者问题 / 推进哪个判断"。标不出来就删、合并或升层。
  - 正例（006）："先承认强 → 再指出边界 → 再放大成本 → 再提出静默降级 → 再回到中文圈和工具链 → 最后升到订阅体系调整"——每一节都比上一节高一层。
  - 正例（010）：六节六重心——§1 事件轴 → §2 GLM 5.2 正面替代 → §3 Kimi K2.7 镜像困境 → §4 监管扩散 → §5 温差框架 → §6 核心判断。每节推进一个独立判断，没有重复。
- **红线（通用）**：A 出现"一笔带过却让读者更疑惑"的句子 / B 退化成产品流水账 / C 退化成资料流水账——判失败。

### LF-5 藏与露（张力靠细节，不靠形容词）

**判据**：最大的信息放进最小的细节 / 最克制的判断；用白描和取舍制造张力，而非用"震撼 / 封神 / 爆炸"这类作者形容硬推情绪。

- `A` 把**信息**藏进细节。正例：范文"他们两人从来不叫对方'宝宝'"。
- `B` 藏掉**实现细节**，露出读者要记住的**判断**。正例：005 藏掉 MCP / CLI / workflow，露出"平台会干活、本地 Agent 懂你、配置不该是用户的工作"。
- `C` 藏掉**调研炫技和资料堆砌**，露出读者需要判断的**边界和后果**。
  - 正例（006）：v1.1 删除"subagent 误判"开头，改用"200 美元跑 3 个任务烧空"直接切入。
  - 正例（010）：52h 调研窗口 + 3 subagent 技术细节只出现在 evolution.md 和文末数据来源中，正文完全不暴露。读者看到的是"6 倍跃升""332 分 187 评论""温差"，看不到作者调用了哪些工具。
- 继承 001 宪法（通用）：观察者姿态、不下结论、结尾定格在画面或一句不解释的话上。

### LF-6 场景调性（人文 / 稳重 > 喧嚣）

**判据**：长文要稳重、引发思考；**商业 / 自媒体 / 直播间 / 路演 / 技术圈狂欢 / 社区情绪的喧嚣感要降为材料**，不作为叙事底色。

- `A` 把采集现场的喧嚣降为脚注。正例：004 把"直播连麦"从导语中移除。
- `B` 判断要落在**日常工作流**，不堆宏大技术叙事或行业口号。正例：005 落点在"写文章前找素材 / 见客户前拼上下文"。
- `C` 热点调研要处理社区情绪，但不能被情绪带跑。
  - 正例（006）：承认"Fable 5 确实很强"，再写"封神有边界"；写"静默降级"时保持"社区担忧 + 机制风险 + 透明度问题"，避免写成阴谋论。
  - 正例（010）：全篇没有一个"炸裂""封神""革命"形容词。最强的语气是"这是第一次"——用事实本身的重量替代形容词。"温差"作为概念锚点，本身就是一个冷静的观察框架，不是情绪宣泄。
- **注意（通用）**：这条与"真实质感 / 非 PR 通稿"红线不冲突——诚实交代信息来源仍要，但**不渲染**喧嚣场景、**不喊**口号。

## B / C 判断型共用维度（A 选配）

### LF-7 观察 → 公共判断

**判据**：判断型长文必须把**一个具体观察**升级成**可迁移的判断**。读者带走的不是"X 发布了什么"，而是"X 让什么分工 / 旧假设 / 趋势变清楚了"。

- `B` 意见型：
  - 正例：005："平台型 Agent 正在变成云端团队，本地 Agent 是你自己的上下文"。
  - 正例：007："Agent 经济的完整回路已经闭合——生产端（Jarred 的 6 步闭环）+ 流通端（x402 的 creator marketplace）"。
- `C` 热点调研型：
  - 正例（006）：从 Fable 5 发布升级到"前沿模型正在从互联网会员产品变回云计算资源"。
  - 正例（010）：**「温差」不是对 GLM 5.2 或 Fable 5 的判断，而是对「如何理解中国 AI 社区」的元判断——一种观察方法本身变成了公共判断。** 与 006 的「订阅体系调整」和 007 的「经济回路闭合」不同，"温差"不是产业结论，是一个可迁移的解释框架：大众层吃瓜 vs 开发者层动手 → 看一个社区要看它的开发者层，不是看热搜。这扩充了 LF-7 的定义域：公共判断可以是一个观察方法，不只是趋势定性。
- **操作**：C 类定稿前自问四句——这个热点说明了什么？它让哪种旧体验失效？它让哪种新成本显性化？它会改变哪一层产业分工？**（010 新增第五问：不同社区层对这个事件的反应差本身说明了什么？）**

### LF-8 传播锚点

**判据**：要有**可传播的判断句**同时承担概念解释 + 文章主线 + 传播记忆点。**锚点策略可以是集中式（一句收束全篇）或散布式（多节各有一个可独立传播的判断句），根据篇幅选择。**

- **集中式锚点**（适合 <2500 字）：
  - 正例：005："平台负责能力。本地 Agent 负责上下文。真正的智能，发生在两者之间。"
  - 正例：007："工厂再大，东西卖不出去，它只是一个车间，不是一个经济体。"
  - 正例：006："模型封神只是新闻。谁能把神请进生产系统里，还不把账单烧穿，才是下一阶段真正的能力。"
- **散布式锚点**（适合 >3000 字长文，010 首证）：
  - §2 标题："不是在比赛，是在填空"——概念锚点
  - §2 结尾："不是一家公司在做。是一个生态在形成。"——证据收束
  - §3 结尾："重复同一个问题，意味着它们已经进入了同一个竞技场"——困境定性
  - §5："温差"——框架命名
  - §6 开头："不是替代，是填空"——核心判断
  - §6 结尾："愤怒会过去。动手的人会留下来"——情感收束
  - 策略选择：010 约 3,400 字，读者可能在任意一节停下来转发。多锚点保证每节都有"能被带走的一句话"。两种策略都是正例，不应强制「一句金句」。
- **注意**：金句 ≠ 营销式"不是 X 是 Y"空话（仍受 `v1-common §4.4` AI 痕迹清单约束）。金句必须**承载真实判断**，靠区分度而非修辞对仗成立。

### LF-9 立场公允 / 反稻草人

**判据**：亮出己方判断前，先**诚实承认对立面或热点对象的合理强项**（steelman），再谈边界、代价和自己的判断。**公允策略有三种，不强制单一方式。**

- **策略 A：先扬后立**（006 正例）——单独一节承认对方强，再展开边界和代价。
- **策略 B：判断+自我限定**（007 正例）——不是承认对立面强（本文没有对立面），而是**主动暴露自己判断的保质期有限**。
- **策略 C：自我引用作为 steelman**（010 首证）——不在正文里花一节承认 Fable 5 的强，而是直接引用自己两周前写的 006 调研："两周前我写过一篇它的全面调研[2]"。效果：(a) 节省篇幅——不用重写论证；(b) 建立可信度——读者知道作者不是"为了现在踩它而假装承认它强"；(c) 形成跨篇互文——006 和 010 构成前后篇；(d) 为读者提供溯源路径——参考资料 [2] 指向 006。
- **红线**：通篇只贬损对立面 / 热点对象、不给对方任何合理性，判失败。

## C 热点调研型专属维度

### LF-10 事实验证优先（B/C 共用）

**判据**：引用外部事实的文章，不论子类型，只要讨论的对象是**冷门 / 新生 / 争议性项目**，就必须先过事实关。**验证方法包括：发布前核验、写作窗口内实时验证、弱信号标注。**

- `B` 意见型：
  - 正例（007）：对 11 项核心事实做了**发布前**浏览器实时验证——HermesHub ⭐数（252）、skill 数（22 vs 691）、x402scan 月交易量（511 万笔）。
- `C` 热点调研型：
  - 正例（006）：官方 benchmark + 社区反馈 + 价格/usage credits 三层事实标签审查。
  - 正例（010）：贡献了两种新增验证方法：
    - **写作窗口内实时验证**——浏览器打开 HN item 48518684，获取实时 332 分/187 评论，直接嵌入正文，**验证改变了数据点**（310→332）。
    - **弱信号交叉验证标注**——US Secretary of War 12p/2c 在正文中明确标注「内容尚未交叉验证」，不删除信号但限制其论证权重。
- **事实层必须区分**：官方事实 / 社区反馈 / 作者判断 / 待验证信息。
- **红线**：未核实的传言写成事实；单条社区反馈写成普遍结论；benchmark 领先直接推导成"全场景替代"；为追热点牺牲事实层级。
- **操作**：定稿前至少做一次"事实标签审查"，给关键句标注：官方事实 / 社区反馈 / 作者判断 / 待验证。凡是标签混乱的句子必须改。**（010 新增：如正文中存在弱信号，需标注「内容尚未交叉验证」或等效表述。）**

### LF-11 账本 / 机制 / 体验三层拆解

**判据**：热点调研型长文不能只写"强不强"，还要拆出"用户真正承担什么"。对科技热点尤其要同时看三层：账本、机制、体验。

- **账本层**：价格、套餐、token、单任务成本、长任务成本。正例（006）：$200 Max 跑 3 个任务烧空。正例（010）：在 §4 中引用 006 的成本数据 + 补充静默降级的信任账本——「被封之前，信任已经在裂了」——把"贵"的概念从「价格贵」扩展到「信任贵」。
- **机制层**：触发条件、降级、分类器、路由、模型分层。正例（006）：safety classifier / PEFT / steering vectors。正例（010）：反蒸馏机制——「Kimi K2.7 也带了反蒸馏机制。和 Fable 5 一模一样。」——用机制层的镜像揭示国产模型也面临同样的困境。
- **体验层**：用户如何感知，工作流如何变化。正例（006）：普通 CRUD vs 复杂重构。正例（010）：V2EX 用户的真实体验——「用过 5.2 回不去 5.1 了」「Kimi2.7 很拉！Token 消耗增高」。
- **红线**：只写能力不写成本；只写价格不写机制；只写机制不写体验；只写社区情绪不写可验证账本。

### LF-12 时效窗口

**判据**：热点调研型文章的版本策略不同于意见型文章。它追求的是**信息窗口期内达到发布标准即发布**，而不是无限打磨到最优版本。**窗口不限于 24h——如果事件在持续发酵，52h 仍在窗口内。**

- **适用条件**：
  - 事件仍在传播窗口内（24-52h）。
  - 事实核验已达基本发布标准。
  - 主线、边界、成本、争议和公共判断已经闭环。
  - Contract 自检通过。
- **窗口弹性**（010 首证）：
  - 正例（006）：24h 内从选题到发布，单窗口快照模式。
  - 正例（010）：52h 内完成，经历了 05:00 + 08:54 两轮数据抓取 + 写作窗口内浏览器实时验证。**多窗口追踪适用于事件持续发酵的热点**——Fable 5 被封后，GLM 5.2 在 HN 上从 120 分涨到 332 分、US Secretary of War 介入、州 AG 调查 OpenAI、监管链条扩展。如果过早发布（如 24h），会错过 §4 的完整监管叙事。
  - 判断标准：**窗口长度由事件演化速度决定，不是由固定小时数决定。** 如果事件仍在产生新的独立信号，窗口仍然开放。
- **红线**：为抢时效牺牲事实核验；为追完美错过热点窗口。

## B 意见型专属维度

### LF-13 概念继承审查

**判据**：意见型文章从选题素材中继承的核心概念，在进入正文前必须过"读者视角三问"——①不读素材原文，读者能秒懂吗？②有没有跟日常语言撞车？③去掉它，判断还成立吗？任一答"否"，就放弃这个概念。

- 正例（007）：全文放弃"造车阶段"框架，改用"Agent 经济的完整回路"。
- 与 LF-3 的分工：LF-3 处理「必须出现但需要解释的词」，LF-13 处理「可以不出现在读者面前的词」。
- `A` 选配；`C` 选配。

## C 热点调研型专属维度（v1.0 新增）

### LF-14 跨层信号识别

**判据**：热点调研型文章如果能识别出**同一事件在不同社区层的反向信号**，并从中提炼出超越事件本身的观察方法，属于加分维度。

- 正例（010）：识别出「微博 0/50 AI 热搜 ≠ 中国互联网不关心 AI」——大众层在吃瓜，开发者层在动手。"温差"作为一个概念框架的提出，源于对两个信号差的观察，最终升维为一种可迁移的观察方法：**看一个社区要看它的开发者层，不是看热搜。**
- 与 LF-7 的分工：LF-7 要求从事件升到公共判断，"温差"在 LF-7 侧是公共判断（"决定 AI 行业走向的是开发者层"）。LF-14 要求从信号差中提炼出观察方法，"温差"在 LF-14 侧是观察方法（"看一个社区要看它的开发者层，不是看热搜"）。两者不重叠：一个是判断（what），一个是方法（how）。
- **注意**：LF-14 不是每篇 C 类都能触发。加分维度，不影响基础评分。
- 目前只有 010 一个正例，暂不要求 ≥2 正例触发编译条件。

## B / C 共用维度（v1.0 新增）

### LF-15 对立面贯穿叙事

**判据**：意见或调研型文章中，如果把一个明确的**对立面**（竞品/反例/被替代对象）作为叙事线索贯穿多节，且对立面在每节中承担不同的论证功能（不是重复出现），属于加分维度。

- 正例（010）：Fable 5 在六节中承担六个不同功能——§1「被封事件」、§2「强但贵但被封锁的对照组」、§3「反蒸馏机制的镜像」、§4「信任崩塌的起点」、§5「大众层吃瓜对象」、§6「被填空的位置」。同一个 Fable 5，六节六个论证功能。
- 反例（假设）：如果每节都在重复"Fable 5 很强但被封了所以国产替代是出路"，对立面就是重复出现而不是功能分化。
- 与 LF-9 的分工：LF-9 管「不能不承认对立面的强」，LF-15 管「对立面可以被调度成多功能的叙事工具」。
- 目前只有 010 一个正例，暂不要求 ≥2 正例触发编译条件。

## 通用 meta 维度（v1.0 新增）

### LF-16 preview → published 编辑模式

**判据**：如果能从 preview→published 的 diff 中提取出可复用的编辑规律，则沉淀为写作→发布的检查清单。这是一个**跨篇积累维度**，不要求单篇文章触发。

- **已识别的编辑模式**（来源：008 + 010）：
  1. **概念落地**——preview 的抽象概念在 published 中被替换为有形状的锚点。"Dario"→"达里奥"（008）、"填空"→"填开源模型的空"（010）、"生态"→"生态的战役"（010）。
  2. **排版呼吸感**——markdown bold 在微信编辑器中被转换为换行 + 短段 + 引号的视觉节奏。preview 保留 `**bold**` 作为语义标记，published 用排版呼吸感做强调。
  3. **段落内人话拉出**——把藏在技术描述里的「读者能感知的不公平」提出来独立成段。如 010 §4 中"用户付的是 Fable 5 的价格，实际拿到的是 Opus 4.8 的答案"从嵌入句变为独立段。
  4. **标题双场景分化**——preview 用概念型标题（适合 GitHub），published 用事件型标题（适合公众号信息流）。不是谁更好，是两个场景的最优解。
  5. **精确 = 补参照物**——"重复同一个问题"→"开始在重复闭源模型的同一个问题"。三个词（"开始""在""闭源"）补了读者能猜出但没写的参照物。
- **操作**：定稿后跑 diff，逐条分类编辑改动。如果发现新的可复用规律，追加到本维度。
- **注意**：本维度是 meta 维度，用于提升写作→发布的编辑质量，不纳入单篇文章的评分。
