# Building Blocks 1.0 — 从 009 全生命周期提炼的写作工程模式

> 来源：drafts/009/evolution.md（v1.0 → v1.1 → v1.1.1 → v1.2 → published）
> 五阶段全生命周期：research → topic card → drafting → quality → publishing
> 日期：2026-06-27

---

## 一、Research → Topic Card（调研到选题）

### 1.1 数据锚点先行

**规则**：每进入一个论点，先把数据摆在句首，再给判断。

**为什么**：读者（尤其是公众号读者）看到"$686.6M（同比+26%）"会在脑中先建立一个量级参考，然后再接受你的分析。反过来——"Xometry 增长非常快，2025 年营收 $686.6M"——读者会在前两个词就流失注意力。

**反例**：不要写"Xometry 的增长令人瞩目"，写"$686.6M（+26%）"。数字本身就是最好的形容词。

### 1.2 5 论点 → 6 章节规则

**规则**：N 个核心论点做成 N 章 + 1 个收束章。

- v1.0：选题卡有 5 个论点 → 写了 6 章（5 论点 + 1 收束）
- 少于 5 章则密度太高，多于 7 章则注意力分散
- 收束章不是总结——是形成最终判准的独立论据

### 1.3 反例权重原则

**规则**：反例只需要说清楚失败原因，不需要给细节。

**案例**：Fast Radius 段落从 7 行压缩到 4 行。删掉了"NYSE: FSRD""SEC 文件里的最后一句话"——读者不需要记住一个退市公司的 ticker。反例的核心功能是：用失败原因反衬成功路径。说清楚"数据不够 + 烧钱快"就够了。

**反例权重公式**：反例篇幅 ∝ 1 / 读者对该案例的熟悉度。越冷门的反例，越要压缩。

## 二、Drafting（写作阶段）

### 2.1 开场：场景 > 数据 > 判断

**规则**：第一段打开具体场景，第二段灌数据，第三段给判断。

**正例**：v1.0 开头——"2013 年，马里兰州小办公室"（场景）→ "$686.6M，1.65 亿零件"（数据）→ "把制造业报价做成了 API"（判断）。

**反例**：不要以"最近，AI 行业…"或"Xometry 是一家…"开头。场景让读者进入画面，数据建立信任，判断锁定注意力。

### 2.2 对比文章不用表格，用逐段展开

**规则**：四家公司对比 = 四段独立段落，不用 markdown 表格。

**为什么**：markdown 表格在手机屏幕上横向滚动，阅读体验极差。逐段展开给每个公司一个独立节奏——读者读完一段形成一个完整印象，再进入下一段。

**模式**：`**Model, Company.**` → 2-3 行公司描述 → 1-2 行数据 → 1 行判断。每个公司 5-7 行。

### 2.3 中美对照文的"防杠"技巧

**规则**：任何中美产业对比文章，必须在给完框架后立刻声明边界。

**模式**："当然，这三个约束不是完整解释。任何一个国家层面的产业差异都有几十个变量在同时作用——政策、教育、文化、地缘。这三个是本文基于 Xometry 赛道最显著的结构性对照，不是唯一解释。"

**为什么**：对比文天然容易触发"美国 > 中国"的简化版解读。边界声明让读者知道：作者承认复杂性，这只是三个最有解释力的变量。

**适用条件**：所有 pillar-4（中美双边视角）文章。

### 2.4 双案例交叉验证

**规则**：单一案例的论证天然脆弱。在判定性段落后，加一个不同行业的平行案例，证明模式的普适性。

**案例**：v1.1 在"B 端 AI 确定性 = 配对数据"段落后，加了肺结节检测 AI（Mayo Clinic 94%）。制造业 + 医疗两个行业同时适用同一框架，读者就无法说"这只是 Xometry 特例"。

**模式**："这其实不是 Xometry 独有的模式。[另一个行业] 也面临同样的结构——[具体数据]。B 端 AI 的确定性，永远建立在配对数据的积累之上。"

### 2.5 结尾从结论变为信号

**规则**：不要用结论收束，用信号收束。

**正例**："它提示了一件事：AI 平台经济，可能不是从最热闹的地方开始的。"

**反例**："它是 AI 平台经济的正确打开方式。"（暗示文章给出了答案）

**为什么**：公众号读者反感姿态。结论 = 你在告诉他们答案。信号 = 你给了一个观察，他们自己判断。

## 三、Quality（质量阶段）

### 3.1 Humanizer：8 条最高频 AI 模式

从 29 条 humanizer 规则中，009 踩中的 8 条（按频率）：

| # | 模式 | 表现 | 替换 |
|---|---|---|---|
| 28 | Signposting | "这篇文章想讲清楚" | 直接提问 |
| 27 | Persuasive authority | "这件事的底层逻辑是""更值得注意的另一件事是" | "说到底""还有一件事" |
| 7 | Overused phrases | "真正有意思的不是…真正有意思的是" | 合并，不重复 |
| 16 | Inline-header lists | "第一种/第二种/第三种/第四种" | **Model, Company.** 自然过渡 |
| 23 | Filler phrases | "无法用资本压缩""不必然等于" | "资本买不来""不等于" |
| 14 | Em dashes | 中文 — 过度使用 | 逗号或句号（中英文混排保留部分） |
| 9 | Negative parallelism | "不是X，而是Y" | **仅当核心判准句时保留** |
| — | 多余引号 | "报价数据""制造能力" | 去引号 |

### 3.2 保留的 AI 模式（有意识地选择）

| 模式 | 保留条件 |
|---|---|
| Negative parallelism | 仅当功能是核心判准句（"不是 AI 不行，是结构化程度不同"），而非装饰性排比 |
| — 分隔线 | 公众号排版结构需求 |
| 数据脚注 | 行业惯例 |

### 3.3 Self-audit：人话检查

写完 v1.2 后问自己："What makes the below so obviously AI generated?"

如果没有明显的 signposting / persuasive authority / mechanical enumeration，就是干净的。

### 3.4 Pillow 自渲染卡片三坑

| 坑 | 表现 | 修复 |
|---|---|---|
| Unicode → 箭头 | 显示为 tofu box | 用 `->` 替代 |
| Em dash 渲染 | Pillow 默认字体不支持 — | 用 `-` 替代 |
| Timeline 文本溢出 | 1800px / 7 节点 ≈ 230px 每节点，>25 英文 char 就会溢出 | 缩短标签或增大画布 |
| 中文 CJK 字体 | Noto Sans 不含中文字形 | 单独加载 Noto Sans CJK（.ttc） |

**验证铁律**：每张自渲染卡必须过 `vision_analyze`。肉眼判断不可靠——v1 版 3 处 bug 全部被 vision 抓到。

## 四、Publishing（发布阶段）

### 4.1 公众号标题 = 信任锚点 + payoff

**公式**：标题 = [信任锚点] + [payoff]

- 信任锚点：让读者相信这不是标题党。"12年亏出来的护城河"（12年 = 数据积累时间，"亏出来的" = 不是吹出来的）。
- Payoff：让读者好奇打开后能得到什么。"Xometry如何用AI把工程师经验变成印钞机"（印钞机 = 利益/价值）。

**反例**："差了一个 Xometry"——有悬念但缺信任锚点，读者不知道是干货还是标题党，不会点。

### 4.2 手机排版：bold 独立段规则

**规则**：每个 bold 独立段必须能独立承载核心论点的 80%。如果所有 bold 行去掉后文章依然完整可读，说明 bold 没打对地方。

**案例**：published 版把以下句子提为加粗独立段：
- "护城河是数据。"
- "是即时报价。"
- "Pure marketplace / 是这条赛道唯一被验证的规模化路径。"
- "B 端 AI 的确定性，永远建立在配对数据的积累之上。"

**为什么**：公众号是扫读媒介。读者滚动时只抓 bold 行，抓到了才停下来读上下文。bold 行是"视觉锚点"。

### 4.3 段落间距：2-3 句一个断点

**规则**：手机屏幕窄，连续 5 行无空行 = 用户跳过。每 2-3 句插入空行断点。

### 4.4 章节编号：01/02/03，不是一/二/三

**规则**：公众号平台用阿拉伯数字编号章节。中文数字笔画多，在小屏幕上拥挤，阅读效率低于阿拉伯数字。

### 4.5 去工具化引用

**规则**：公开发布内容里不能出现内部工具名。

| 禁止 | 替代 |
|---|---|
| "inbox 里列出的" | "另外三家" |
| "选题卡编号 007" | "我之前写的 'Agent 经济的完整回路已经出现'" |
| "draft v1.2 里" | 不需要——读者不知道什么是 draft |

**原则**：读者能接受的是"我之前写过的一篇文章"这类自然引用。作者和 agent 之间的协作语言（inbox/draft/topic card）在公开发布内容里全都不可见。

### 4.6 副标题价值

**规则**：读者打开文章后第二眼落在副标题上。副标题必须在 2 秒内给出核心 takeaway。

**模式**：`"Xometry 是全球第一个跑通'AI 即时报价 + 全球供应商网络'的 industrial marketplace"`——独立成行，加粗，放在标题和正文之间。

### 4.7 负数格式

`$(5.3)M` → `(5.3)M`。括号已表负数，不加 `$`。

### 4.8 数据来源 → 参考资料

"数据来源" → "**参考资料**"。更自然，不那么学术气。
